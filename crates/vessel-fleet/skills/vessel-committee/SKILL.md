# Vessel Committee

Read the vessel skill. Select two suitable profiles after reading their notes;
when possible choose different provider families and reasoning styles. Honor
the user's specified members. If fewer than two suitable profiles are offered,
use provider discovery for the missing member and disclose that fallback.

Prepare the same self-contained problem for both members: the intended result,
observed evidence, relevant paths, constraints, failed approaches and the
specific decision needed. Ask for causes, alternatives, tradeoffs and a plan.
Do not turn a planning request into permission to implement.

End each briefing with:

> Analyze and recommend only. Do not edit, create or delete files, implement
> changes, or change running services.

Create two `[Committee]` sessions with completion notifications. Independent
analysis may take time. Do not poll, send hurry-ups or interrupt them to ask
for progress. Continue independent work, then finish your turn for the notices.

Wait for both analyses. Compare their evidence and assumptions. Pass concrete
disagreements between the same members, preserving the analysis-only boundary,
and check claims that can be tested directly within the authorized scope.
Seek a reasoned resolution rather than counting votes. If a disagreement
requires unavailable evidence, retain it explicitly instead of claiming a
consensus. Present one actionable plan and the material disagreements that
remain. Implementation stays with the authorized task owner.
