## 1. Composer shell (`Composer` -> `MessageInput`)

### 1.1 What the user sees
- `Composer` (`app:composer/index.tsx:1213`, body `ComposerContentImpl` `:1239`) wraps one `MessageInput` (`app:composer/input/input.tsx:1227`). Hosted by the agent panel (`app:panels/agent-panel.tsx:~1620-1660`, `<Composer ... onClientSlashCommand={handleClientSlashCommand}>`), by draft tabs (`app:composer/draft/workspace-tab.tsx`), and in a "terminal" mode (below).
- Layout pieces: attachment tray (above the text, `renderAttachmentTray` `index.tsx:338`), queue track (`renderQueueTrack` `:383`), send-error line (`sendError` state), autocomplete popover anchored to the input (`ComposerAutocompleteBinding` `:1000`), left slot = agent controls (mode/model/thinking, other area), right slot = context-window meter + voice-mode button + dictation mic + attach button + Send/Stop button, `ComposerTrackBar` of ambient pills (`app:composer/tracks.tsx`: task list, subagent/diff-stat pills; not input).
- Composer modes (`app:composer/input-mode.ts`): `"chat"` (attachments, voice, autocomplete, agent controls all on) and `"terminal"` (all four off, monospace font, accessibility label `composer.input.terminalAccessibilityLabel`; used for a terminal prompt that becomes argv).
- `readOnly` prop disables editing/fullscreen; `submitBehavior` = `"clear"` (default) or `"preserve-and-lock"` (text stays, composer locked while `isSubmitLoading`, used by the new-workspace flow; `resolveIsComposerLocked` `index.tsx:200`); `submitIcon` `"arrow" | "return"`, `submitLabel`, `allowEmptySubmit`, `hasExternalContent`, `waitForForgeAutoAttachOnSubmit`, `blurOnSubmit` (native only), `placeholder`.
- Placeholder: `resolveMessagePlaceholder` `index.tsx:227` (i18n `composer.placeholders.*`, fallback `composer.placeholders.fallback`); desktop layout vs compact use different strings.
- Auto-height: `useComposerHeight` (`app:composer/input/height.web.ts`, `height.native.ts`): web measures with a hidden mirror textarea copying fonts/padding; min height `MIN_INPUT_HEIGHT_DESKTOP = 46` (web) / `MIN_INPUT_HEIGHT_MOBILE = 30` (native); max height = `max(DEFAULT_MAX_INPUT_HEIGHT = 160, floor(windowHeight * MAX_INPUT_VIEWPORT_RATIO = 0.5))` on non-compact, 160 on compact (`input.tsx:216-220,1046`). After a send the height resets (`minimizeInputHeight`) except under `preserve-and-lock`.
- Fullscreen editor: only on compact form factors (`shouldShowFullscreenControl`: `compact && !readOnly && !overlayVisible && renderedLines > 2`, `input.tsx:1218`). Maximize/Minimize glyph in the text surface (`app:composer/input/presentation.tsx`), Escape/hardware back exits (`app:composer/input/fullscreen-exit*.ts`, gated to the active pane via `useComposerKeyboardScope`). Entering dictation, voice mode, or sending exits fullscreen. Dock components (`app:composer/dock/index.tsx`, `index.native.tsx`, `internal/capacity.ts` `resolveInlineComposerCapacity`) size the inline composer against the viewport and let the same mounted editor fill the slot in fullscreen. Send is disabled in fullscreen with no sendable content (`resolvePresentationSendDisabled` `input.tsx:1205`).
- Editing session (`app:composer/editing-session/index.tsx`, `ComposerEditingSession`): carries caret selection, focus intent and fullscreen flag across remounts (compact <-> desktop breakpoint swap mounts a different tree); `insertCommand(command)` appends `"<command> "` to the text (used by "insert command" callers). Draft text itself lives in the draft owner, not the editor.
- Focus: desktop autofocus only when `autoFocus && isDesktopWebBreakpoint && hasFinePointer` (touch screens never autofocus to avoid the soft keyboard); `focusWithRetries` util re-tries focus until `document.activeElement === textarea`; `autoFocusKey = serverId:agentId:<attachmentFocusRequestId>` so "attach file to chat" refocuses (see 6.6).

### 1.2 State and persistence (end to end)
- Text and attachments belong to a **draft owner** (`useAgentInputDraft`, `app:composer/draft/input-draft.ts:71`) passed to `Composer` as `textSource` (external-store: `getSnapshot/subscribe`), `onChangeText = editText`, `textReplacement`, `attachments`, `onChangeAttachments = setAttachments`, `clearDraft`.
- Draft key = `buildDraftStoreKey({serverId, agentId, draftId?})` (`app:stores/draft-keys.ts:25`): `agent:<serverId>:<agentId>` for an existing agent, `draft:<serverId>:<draftId>` for a draft tab; `NEW_WORKSPACE_DRAFT_KEY = "new-workspace"` and `new-workspace:draft:<id>` for the new-workspace composer.
- Store: `useDraftStore` (zustand + `persist`, `app:stores/draft-store/index.ts:253`, storage name `"paseo-drafts"`, `DRAFT_STORE_VERSION = 5` in `state.ts:9`). Persisted through `AsyncStorage` (web = localStorage shim, native = RN AsyncStorage) wrapped by `createValidatedPersistStorage(AsyncStorage, PersistedDraftStoreSchema)` and `createDraftPersistStorage` which **throttles writes to at most one per `DRAFT_PERSIST_INTERVAL_MS = 200`** with a trailing write and `flushDraftPersistStorage()` (`persistence.ts`).
- Record shape: `DraftRecord {input:{text, attachments}, lifecycle: "active"|"abandoned"|"sent", updatedAt, version}`; state = `{drafts: Record<key, DraftRecord>, createModalDraft}`. Actions: `getDraftInput`, `hydrateDraftInput` (async; migrates legacy images/shape, `migration.ts`), `saveDraftInput`, `editDraftText`, `markDraftLifecycle`, `clearDraftInput({draftKey, lifecycle?})`, `attachWorkspaceFile`, `getCreateModalDraft/saveCreateModalDraft`, `collectActiveAttachmentIds`. Runtime-only: `attachmentFocusRequestByDraftKey`.
- Empty text + no attachments => draft becomes `lifecycle:"abandoned"` (`saveDraft`/`editDraftRecordText`). Finalized (non-active) records are pruned after `FINALIZED_DRAFT_TTL_MS = 5 * 60 * 1000` (`pruneFinalizedDraftRecords`, run inside attachment GC).
- Web typing path: `editText` stages text through `AfterPaintPublication` (`app:composer/after-paint-publication.ts`) so the store is written after paint, not per keystroke; flushed on `visibilitychange` (hidden), `pagehide` and unmount. Native writes immediately. `replaceText` cancels staged text, writes the store and publishes a `TextReplacement {kind:"initial"|"hydrated"|"replace", key, text}` that the editor applies once per key (`resolveComposerSurfaceText`, `app:composer/input/state.ts:255`).
- On mount the draft hook awaits `hydrateDraftInput({draftKey})` then publishes a `"hydrated"` replacement and sets `isHydrated`.
- Cleared with `clearDraft("sent")` after a successful send and when a client slash command runs; `"abandoned"` for dismissals.
- Draft agent-creation drafts (draft tabs): `useAgentInputDraft` with `composer` options also wraps `useAgentFormState` (provider/model/mode/thinking/feature selection) and exposes `composerState.agentControls` and `commandDraft` (a `DraftCommandTarget` for slash-command listing before an agent exists); create flow state machine `app:composer/draft/create-flow.ts` (`draft` -> `creating` -> `CREATE_FAILED` back to `draft`, optimistic user message via `handoffCreatedAgentMessageSubmission`). The create RPC itself belongs to the agent-creation area.

### 1.3 Limits and defaults
- Send shortcut setting `sendShortcut: "enter" | "mod-enter"` default `"enter"`; send-while-running behaviour `sendBehavior: "interrupt" | "steer" | "queue"` default `"steer"` (`app:hooks/use-settings/storage.ts:36,84,109,145,166,225,271`). Settings UI: `app:screens/settings/general/sending-section.tsx` (Command+Enter row text switches when `sendShortcut === "mod-enter"`).
- `shouldSubmitOnEnter = isWeb && !isCompact`: on compact/native, Enter inserts a newline and only the Send button sends.

### 1.4 Platforms
- Web/desktop: key handling in `handleDesktopKeyPressImpl` (`input.tsx:423`), IME composition guard `isImeComposingKeyboardEvent`. Native: Send button only (long-press = alternate send with a medium haptic).
- Electron adds the file-based attachment store and native dialogs (sections 5).

### 1.5 Connections
Reads agent turn state (`selectAgentTurnPresentation`), pending permissions, serverInfo capabilities, checkout status (forge remote URL), settings; writes draft store, session-store queue and message submissions, workspace-attachments store; triggers dictation, realtime voice, agent send/cancel RPCs, client slash commands (archive/new draft), plugin slash commands and attachment sources. Mounted keyboard handler registers actions `agent.interrupt, message-input.focus|send|dictation-toggle|dictation-cancel|dictation-confirm|voice-toggle|voice-mute-toggle` (`ComposerKeyboardRegistration` `index.tsx:582`) with priority 200 when the input is focused else 100, enabled only for the active composer pane (`useComposerKeyboardScope`, `app:composer/keyboard-scope.tsx`).

## 2. Send, interrupt, steer (submit path)

### 2.1 What the user does
- Send button (arrow), Enter (default shortcut), Mod+Enter (alternate), long-press Send on touch (alternate). While the agent runs and the draft is empty the Send slot shows the **Stop** square (`resolvePrimaryActionKind` `input.tsx:857`, `ComposerCancelButton` `index.tsx:1092`, tooltip `composer.cancel.interrupt` + shortcut chord of `agent-interrupt`).
- Keyboard map (`app:keyboard/keyboard-shortcuts.ts:1052-1175`): `Cmd/Ctrl+L` focus input; `Shift+Tab` cycle agent mode (when `focusScope: "message-input"`, handled by agent controls); `Cmd/Ctrl+Shift+D` toggle voice mode; `Cmd/Ctrl+D` start/stop dictation; `Escape` = `agent.interrupt`; `Enter` while dictating = confirm-and-send (`dictation-confirm`); `Space` (focusScope `other`) mute/unmute voice mode.
- Enter semantics (`resolveMessageInputEnterAction` `app:composer/input/state.ts:167`): requires `submitOnEnter`; Shift always newline; with `sendShortcut "mod-enter"` plain Enter = newline, Mod+Enter = default send; with `"enter"` Mod+Enter while agent running and `onQueue` exists = alternate send, otherwise default send.
- Default vs alternate action (`runDefaultSendAction`, `resolveAlternateSendAction`, `state.ts:~140-165`): if agent running and the effective behaviour is `"queue"` default = queue and alternate = send now; otherwise default = send (interrupt/steer) and alternate = queue. No running turn -> both = send. `resolveActiveSendBehavior` (`state.ts:9`) forces `"queue"` -> `"interrupt"` when the agent has a **pending permission** request (queued messages would be stranded behind a parked turn).
- Escape (`agent.interrupt`, `dispatchComposerKeyboardAction` `index.tsx:548`): first tries `runKeyboardAction("dictation-cancel")`; else cancels the agent if running, not already cancelling and connected.

### 2.2 End-to-end (default send, agent idle or interrupt/steer)
1. `MessageInput.handleSendMessage` (`input.tsx:1660-ish`, `sendMessageImpl` `:977`) trims text; returns if empty and no attachments/external content/`allowEmptySubmit`; exits fullscreen; calls `onSubmit({text, attachments, cwd, forceSend: isAgentRunning || undefined})`.
2. `Composer.handleSubmit` (`index.tsx:1715`): `buildOutgoingAttachments(attachments)` (merges user attachments with workspace attachments, 6.7); client slash command check (3.1); plugin slash command check; `blurOnSubmit` on native; `sendMessageWithContent`.
3. `submitAgentInput` (`app:composer/submit.ts:25`, result `"noop"|"queued"|"submitted"|"failed"`): no-op if empty or `!canSubmit`; if `isAgentRunning && !forceSend` -> queue; else clears text and attachments immediately (unless `preserve-and-lock`), `setSendError(null)`, `setIsProcessing(true)`, awaits `submitMessage`, then `clearDraft("sent")`; on error restores text/attachments, sets `sendError` (error message or i18n `composer.errors.failedToSend`), logs `[AgentInput] Failed to send message`.
4. `submitMessage` (`index.tsx:1539`): `onMessageSent`; if a parent supplied `onSubmitMessage` (draft create flow) it takes over; else `dispatchComposerAgentMessage` with `activeTurnBehavior = appSettings.sendBehavior === "steer" ? "steer" : "interrupt"` (note: `"queue"` setting sends as `"interrupt"` when force-sent) and for steer the current `turnId` (`selectAgentTurnPresentation(...).turnId`). Then `onAttentionPromptSend` (clears attention).
5. `dispatchComposerAgentMessage` (`app:composer/actions.ts:202`): `splitComposerAttachmentsForSubmit` (6.7) -> `{images, attachments}`; generates `clientMessageId` (`generateMessageId`); builds an optimistic `UserMessageItem` (`createUserMessage`, with `turnId` for steer) and calls `submission.begin` (adds it to the stream tail via `beginAgentMessageSubmission` when the daemon has `features.canonicalSubmittedPrompts`, else `appendSubmittedUserMessage` untracked); encodes images to base64 (`encodeImages` = `encodeAttachmentsForSend`, 5.4); `client.sendAgentMessage(agentId, text, {messageId: clientMessageId, activeTurnBehavior, images, attachments})`; on success `submission.accept`; on failure `submission.reject` (removes the optimistic row if the provider had not acknowledged; `rejectMessageSubmission` outcome `"rejected"|"accepted"|"unknown"`) and rethrows.
6. Client (`client:3887 sendAgentMessage`): sends `send_agent_message_request {requestId, agentId, text, messageId, activeTurnBehavior?, images?, attachments?, sourceAgentId?, sourceAgentServerId?, sessionMode?}` (proto `SendAgentMessageRequest`, fields at `proto:messages.ts:~1425-1436`) with `skipQueue`, awaits `send_agent_message_response {requestId, agentId, accepted, error, deliveryStatus?: "queued"}`; throws `payload.error ?? "sendAgentMessage rejected"` when not accepted. Provenance fields need `serverInfo.features.agentMessageProvenance` / `agentMessageBatching`.
7. Server `handleSendAgentMessageRequest` (`srv:session.ts:8304`): resolve agent id (full id, prefix or exact title); `buildAgentPrompt(text, images, attachments)` (`srv:agent/prompt-attachments.ts:7`: plain trimmed string when no images/attachments; else content blocks = chat-history text attachments first, then text, then `{type:"image",data,mimeType}` blocks, then other attachments; `renderPromptAttachmentAsText` renders forge CR/issue, text, review, `uploaded_file` as `Uploaded file: <name>\nPath: <path>\nMIME: ...\nSize: N bytes`); if `messageId` present goes through `MessageReceipts.send` (`srv:message-receipts/index.ts`: idempotency via `paseoHome/agent-requests/<sha256>.json` with `state: pending|completed`; same id + different fingerprint = error `agent_request_key_conflict`; pending leftover = `agent_request_outcome_unknown`) whose `prepare` sets a provisional title from the first message if the agent has no title and no `lastUserMessageAt` (`prepareAgentMessage` `:8291`). Dispatch: agent-sourced messages go through `agentMessages.enqueue` (default `steer`, response `deliveryStatus:"queued"`); human messages go through `sendPromptToAgent` -> `sendPreparedPromptToAgent` (`srv:agent/agent-prompt.ts`): unarchives archived agents, loads the agent, optionally sets `sessionMode`, then `startAgentRun` (`:91`) with `replaceRunning: true`, `activeTurnBehavior` default **`"interrupt"`**, `clearPendingPermissions: true` (a human message answers any blocked permission). `startAgentRun` order: `tryRunOutOfBand` (e.g. provider `/goal pause` runs without cancelling a turn) -> `reloadStalePluginSession` -> if `steer`: `steerOrReplaceActiveTurn` (waits for a still-starting turn, provider `steerActiveTurn` with `expectedTurnId`; if the provider cannot steer the active turn is replaced) -> else `replaceAgentRun` when a run is in flight, otherwise `streamAgent`. Returns `out_of_band|steered|turn_started`; for `turn_started` waits for run start, bounded by `AGENT_RUN_START_TIMEOUT_MS = 60_000`. Stale provider session errors reload the session once and retry.
8. Events back: the timeline stream delivers the canonical `user_message` (proto `agent-types.ts:376`: `{text, messageId?, clientMessageId?}`); `observeMessageSubmissionCanonical` (`app:composer/submission/model.ts`) marks the submission `providerAcknowledged`; the optimistic row (which carries images/attachments metadata locally) is merged with the authoritative row (`app:types/stream.ts` keeps submitted `images`, see tests "preserves submitted user message images"). `hasActiveMessageSubmission` feeds `selectAgentTurnPresentation` so the UI shows running immediately.

### 2.3 Stop / interrupt
- `handleCancelAgent` (`index.tsx:1894`) -> `cancelComposerAgent` (`actions.ts:178`; no-op unless running, not cancelling, connected) -> `client.cancelAgent` (`client:3980`) -> `cancel_agent_request {agentId, requestId?}` -> `handleCancelAgentRequest` (`srv:session.ts:4838`) -> `cancelAgentRunCommand` (`srv:agent/lifecycle-command.ts:96`; throws `AgentRunCancellationError` when the agent reports running but nothing could be cancelled) -> `cancel_agent_response {agentId, agent, error}`.
- UI state: `getHostRuntimeStore().beginAgentCancellation/settleAgentCancellation(serverId, agentId, requestId)` drives `isCancelling` in turn presentation (spinner replaces the square, label `composer.cancel.cancelingAgent`); errors toast. Focus returns to the input after pressing Stop.

### 2.4 Message queue ("queue while the agent works")
- Queue is **client-only, in memory**: `SessionState.queuedMessages: Map<agentId, {id, text, attachments}[]>` (`app:stores/session-store.ts:447`, setter `setQueuedMessages`). Not persisted, not sent to the daemon, lost on reload (except image blobs, kept alive by the GC, 5.5).
- `queueComposerMessage` (`actions.ts:246`): trims text, drops if empty and no attachments, appends `{id: generateMessageId(), text, attachments}`. After queueing the composer clears text/attachments/suppression (`queueMessage` `index.tsx:1631`).
- Queue rows (`QueuedMessageRow` `index.tsx:673`): 2-line truncated text, Edit (pencil) -> `editQueuedComposerMessage` removes it from the queue and puts text + user attachments back in the composer; Send-now (arrow) -> `sendQueuedComposerMessageNow` removes then submits through the normal path (daemon interrupts the active run atomically); on failure the item is re-inserted at the front and the error shown.
- Auto-drain: `HostRuntime.drainQueuedAgentMessage` (`app:runtime/host-runtime.ts:2563`) is invoked when an agent stops running (`onAgentStoppedRunning`) and after an authoritative timeline sync when `agent.turn.phase === "idle"` (`app:timeline/viewed-timeline-sync.ts:261`). It sends the **first** queued item with `activeTurnBehavior: "steer"` (so a turn that started on its own in that moment absorbs it instead of being interrupted); guarded by `queuedAgentDrainInFlight` and `initializingAgents`; failures only `console.error`. One message per drain; the next drains when that turn ends.
- Dictation auto-send respects the same rule (`applyDictationTranscript`, 4.4).

### 2.5 Errors and states
`sendError` text under the queue; Send button shows spinner while `isProcessing || isSubmitLoading || isUploadingFile || pendingNativeImagePastes > 0`; Send disabled also while forge auto-attach is resolving when `waitForForgeAutoAttachOnSubmit`; disconnected host -> `workspace.terminal.hostDisconnected` error; dictation/voice buttons disabled when not connected.

### 2.6 History recall (Up/Down)
`ComposerRecall` (`app:composer/recall.ts:13`): from an empty composer, ArrowUp recalls the agent's previously sent messages newest first (`selectAgentSentMessages` `session-store.ts:336`: user_message items in the in-memory stream tail+head, trimmed non-empty, consecutive duplicates collapsed); ArrowUp/Down continue only while the text still equals the recalled text, selection is collapsed, caret is on first/last line, no modifier; ArrowDown past newest restores empty. The autocomplete popover wins the arrows when open; a recalled message is never treated as a `/command` for autocomplete (`recall.isShowing`). Recall is limited to what is loaded in the stream (not the whole persisted timeline).

## 3. Slash commands and autocomplete

### 3.1 Client slash commands (`app:client-slash-commands/index.ts`)
- `CLIENT_SLASH_COMMANDS`: `/exit` (aliases `quit`, `q`; kind `archive-agent`; "Archive the current agent") and `/clear` (alias `new`; kind `replace-agent-with-draft`; "Archive this agent and start a fresh draft"). Both `execution: "immediate"`. i18n keys `composer.clientCommands.archiveAgent|freshDraft`.
- `resolveClientSlashCommand({text, hasAttachments})`: only when the whole trimmed text is `/name` with no whitespace and **no attachments**; `COMMAND_BY_NAME` includes aliases.
- Execution (`runClientSlashCommand` `index.tsx:1422`, host handler `handleClientSlashCommand` `app:panels/agent-panel.tsx:1580`): clears draft (`clearDraft("sent")`), text, attachments, error; sets processing; calls `onClientSlashCommand(command)`: unpin + hide the agent in the workspace tabs, then `/clear` retargets the current tab to a new draft with `buildDraftAgentSetup(agent)` (same provider, cwd, mode, model, thinking option, feature values) or `/exit` closes the tab, then `archiveAgent({serverId, agentId})` (archive RPC, other area). Errors set `sendError`.
- Both Send and Queue paths run client slash commands first (so `/exit` while the agent works still archives).
- Hidden in draft contexts: built-in commands are filtered out when the composer is a draft (`isDraftContext && source === "built-in"` in `buildCommandAutocompleteOptions`).

### 3.2 Plugin client slash commands (`app:plugins/client-slash-commands/`)
- `usePluginClientSlashCommands({serverId, workspaceId, agentId})` builds `{pluginId,name,description,argumentHint,run(args)}` from installed plugins' `clientSlashCommands` contributions (context `"agent"` needs the agent in client state; `"workspace"` needs the workspace). Parsed with `resolvePluginClientSlashCommand`: `/^\/([^\s]+)(?:\s+([\s\S]*))?$/` on trimmed text, args trimmed, ignored with attachments. Executed via `executePluginClientSlashCommand`; errors toast.
- Merge order (`mergeSlashCommandSources` `model.ts`): built-in first, then plugin (a plugin command colliding with a built-in name or alias is ignored with a `console.warn`), then provider commands not already claimed.

### 3.3 Agent-provided (provider) commands and skills
- Trigger: typing `/` at the start (or after whitespace, `position:"inline"`) opens the popover. `findActiveSlashCommand` (`app:utils/agent-command-autocomplete.ts:87`): the nearest `/` before the cursor whose previous char is whitespace/start and whose query contains none of `/ whitespace " '`. Inline (non-start) position lists only provider commands with `kind === "skill"` (`filterInlineSkillCommandEntries`).
- Listing: `useAutocompleteCommands` -> `useAgentCommandsQuery` (`app:agent-commands/use-query.ts`): `client.listCommands({agentId, draftConfig?})` -> `list_commands_request {agentId, requestId, draftConfig?:{provider,cwd,modeId?,model?,thinkingOptionId?,featureValues?}}` -> `handleListCommandsRequest` (`srv:session.ts:5096`): if the agent exists (or stored and not archived) it is loaded and `agent.session.listCommands()` answers; else with a `draftConfig` `agentManager.listDraftCommands(sessionConfig)` (cwd tilde-expanded); else error `Agent not found: <id>` / `Agent does not support listing commands`. Response `list_commands_response {agentId, commands:[{name, description, argumentHint, kind?: "command"|"skill"}], error, requestId}`.
- Query policy (`app:agent-commands/cache/index.ts`): session commands `staleTime 600_000`, `gcTime 1_800_000`, refetch on mount, no refetch on focus; draft queries immutable once fetched; retry 3 with exponential backoff capped 5s; enabled only while the retained panel is active and the host is connected. Provider snapshot changes (status/enabled/source/models/modes/default mode) invalidate matching catalogs (`invalidateCommandsForProviderChange`).
- Ranking: `filterAndRankCommandAutocompleteEntries` using `scoreTextFields` from `proto:search/text-match` over name + aliases; empty query keeps source order; ties by name.
- Selection (`onSelectOption` in `use-agent-autocomplete.ts:~470`): immediate client command with no attachments executes at once; otherwise `applySlashCommandReplacement` writes `/name` (+ trailing space when at end of text) and refocuses the input; Escape on a start-position command clears the whole input.
- Popover states: loading (`agentAutocomplete.loadingCommands`), error (`agentAutocomplete.failedToLoad` or the server error), empty (`agentAutocomplete.noCommands`), draft not ready (`chooseProjectForCommands` when no project, `chooseModelForCommands` when no provider).
- Sending a provider slash command is just a normal prompt string; the provider interprets it (server does not parse it, except `tryRunOutOfBand`).

### 3.4 File mentions (`@`)
- `findActiveFileMention` (`app:utils/file-mention-autocomplete.ts:20`): scans back for `@` not preceded by a word char or `+` (so emails are skipped), query must not contain whitespace or `"'<>`.
- Search: debounced 180 ms; `client.getDirectorySuggestions({cwd, query, limit: 50, includeFiles:true, includeDirectories:true})` -> `directory_suggestions_request {query, cwd?, includeFiles?, includeDirectories?, matchMode?: "fuzzy"|"suffix", limit?(1-100), requestId}` -> `handleDirectorySuggestionsRequest` (`srv:session.ts:5221`; `searchDirectoryEntries` with `pathFormat:"relative"`, `blankQueryBehavior:"children"`, `respectGitIgnore`, `traversableHiddenDirectoryNames: WORKSPACE_SEARCH_HIDDEN_DIRECTORIES`; without `cwd` it searches HOME with absolute paths) -> `directory_suggestions_response {directories, entries:[{path,kind}], error, requestId}`. React-query `staleTime 15_000`, `keepPreviousData`, no retry. cwd = agent cwd (or draft config cwd); no cwd -> popover not shown.
- Selection inserts a **quoted relative path** `"path"` (`formatQuotedFileMentionPath`, inner `"` escaped as `\"`), replacing `@query`; the agent receives it as plain text (no structured attachment).
- Mention of "other things" (sessions, agents, terminals): **not found** in the composer; searched `app:hooks/use-agent-autocomplete.ts`, `utils/*-autocomplete.ts`. Only commands and file/dir paths exist. Issues/PRs are attached through the picker (6.4) or auto-attach on pasted URLs (6.5).

### 3.5 Autocomplete popover mechanics
`useAutocomplete` (`app:hooks/use-autocomplete.ts`): ArrowUp/Down (move, `getAutocompleteNextIndex`), Tab/Enter (select; fallback index = first/last depending on `optionsPosition`), Escape (optional `onEscape`); selected index resets when the query changes. `ComposerAutocomplete` renders `AutocompletePopover` only for the active composer pane. Shown only when `mode.showAutocomplete && !isFullscreen`.

## 4. Dictation (speech to text)

### 4.1 What the user sees
- Mic button in the input row (`VoiceButtonTooltip` `input.tsx:742`, label `composer.voice.startDictation|stopDictation`, tooltip `composer.voice.dictation` + `dictation-toggle` chord). Press = start; press while recording = cancel (`handleVoicePressImpl` `:957`); when realtime voice is active for this agent the same button toggles mute instead.
- While recording/processing/failed the input is covered by `DictationOverlay` (`app:components/dictation-controls.tsx`): X cancel (or discard when failed), volume meter (`VolumeMeter`), mm:ss timer (`formatDuration`; shows `message.dictation.paused` when status `paused`), then **Insert** (pencil/check) and **Insert and send** (arrow); spinner while processing; **Retry** (refresh icon) when failed with text `message.dictation.failed` / `failedRetry`. A simpler inline `DictationControls` variant (mic + timer + same actions) exists in the same file.

### 4.3 End to end
- Hook `useDictation` (`app:hooks/use-dictation.ts:17`; shared types/constants `use-dictation.shared.ts`: `DictationStatus = idle|recording|paused|uploading|failed`, `PCM_DICTATION_FORMAT = "audio/pcm;rate=16000;bits=16"`, `DURATION_TICK_MS = 1000`). Options `onTranscript`, `onPartialTranscript`, `onError`, `onPermanentFailure`, `canStart`, `canConfirm`, `enableDuration` (the composer enables the timer through the overlay).
- Audio capture (`app:hooks/use-dictation-audio-source.{web,native}.ts`):
  - Web/Electron: `getUserMedia({audio:{channelCount:1, noiseSuppression:true, echoCancellation:true, autoGainControl:true}})`, `AudioContext` + `ScriptProcessor(4096)`, RMS volume `min(1, rms*2)`, resample to 16 kHz PCM16 (`resampleToPcm16`, `app:audio/pcm/index.ts`), emit **~1 s segments (16000 samples)** as base64. Needs a secure context (HTTPS/localhost) except under Electron. Fallback: `MediaRecorder` blob, decoded (WAV parse or `decodeAudioData`) then segmented the same way.
  - Native: `createAudioEngine(..., {captureMode:"dictation"})` -> `expo-two-way-audio` `startDictation()` (see 7.4); `onCaptureData` PCM -> base64 segments; `onCaptureAvailabilityChange(false)` -> status `paused`; `onInterruption` -> fail with "Dictation was interrupted by another audio source." Microphone permission requested via `getMicrophonePermissionsAsync/requestMicrophonePermissionsAsync`; error text "Microphone permission is required...".
- `DictationStreamSender` (`app:dictation/dictation-stream-sender.ts:51`): ordered buffer of base64 segments with sequence numbers; `restartStream` creates a new `dictationId` (`generateMessageId`) and `startDictationStream`; chunks flushed in batches of `MAX_CHUNKS_PER_FLUSH_TURN = 128` per macrotask; acks from `dictation_stream_ack` (`ackedSeq`); a reconnect (`subscribeConnectionStatus` -> connected while recording) starts a **new stream and replays all buffered segments** (lossless resumable); finish waits for ack drain with idle timeout `DICTATION_DRAIN_IDLE_TIMEOUT_MS = 30_000` (then `Timed out waiting for dictation stream delivery`), then `finishDictationStream`.
- Client methods (`client:4282-4500`): `startDictationStream` waits for `dictation_stream_ack` with `ackSeq == -1` (30 s) or `dictation_stream_error`; `sendDictationStreamChunk` (strict send); `finishDictationStream(dictationId, finalSeq)` waits for `dictation_stream_finish_accepted {timeoutMs}` (accept timeout `DEFAULT_DICTATION_FINISH_ACCEPT_TIMEOUT_MS = DEFAULT_SESSION_RPC_TIMEOUT_MS`) then `dictation_stream_final` within `timeoutMs + DEFAULT_DICTATION_FINISH_TIMEOUT_GRACE_MS (5000)`; fallback `DEFAULT_DICTATION_FINISH_FALLBACK_TIMEOUT_MS = 5 min`; `cancelDictationStream`.
- Protocol (`proto:messages.ts:1712-1736, 3567-3612`): in `dictation_stream_start {dictationId, format}`, `dictation_stream_chunk {dictationId, seq, audio(base64), format}`, `dictation_stream_finish {dictationId, finalSeq}`, `dictation_stream_cancel {dictationId}`; out `dictation_stream_ack {dictationId, ackSeq}`, `dictation_stream_finish_accepted {dictationId, timeoutMs}`, `dictation_stream_partial {dictationId, text}`, `dictation_stream_final {dictationId, text, debugRecordingPath?}`, `dictation_stream_error {dictationId, error, retryable, reasonCode?, missingModelIds?, debugRecordingPath?}`.
- Server routing: `dispatchVoiceAndControlMessage` (`srv:session.ts:2741`) -> `VoiceSession` (`srv:session/voice/voice-session.ts:166`, `handleDictationStreamStart` checks readiness via `resolveVoiceFeatureUnavailableContext("dictation")`, emitting `dictation_stream_error` with `reasonCode`/`missingModelIds`) -> `DictationStreamManager` (`srv:dictation/dictation-stream-manager.ts:129`).
- Manager behaviour: resolves STT provider (`Dictation STT not configured` error, non-retryable); creates `StreamingTranscriptionSession` with language (default `"en"`, configured via `PASEO_DICTATION_LANGUAGE` / `features.dictation.stt.language`) and a fixed prompt (`PASEO_DICTATION_TRANSCRIPTION_PROMPT`, default "Transcribe only what the speaker says ... return an empty transcript for silence"); input rate parsed from the format, resampled with `Pcm16MonoResampler` to the provider's `requiredSampleRate`; chunks reorder by `seq` (`receivedChunks`, duplicates re-acked, mismatched format fails the stream); **auto-commit** a segment every `DEFAULT_DICTATION_AUTO_COMMIT_SECONDS = 15` of audio (env `PASEO_DICTATION_AUTO_COMMIT_SECONDS`, 0 disables) unless the segment peak abs < `DICTATION_SILENCE_PEAK_THRESHOLD = 300` (env `PASEO_DICTATION_SILENCE_PEAK_THRESHOLD`; silence is `clear()`ed); on finish: seal (commit tail unless silent), wait for all segment transcripts final, join segments with a space -> `dictation_stream_final`; finish with `finalSeq >= 0` but zero chunks received fails fast (retryable). Finalize timeout = `max(DEFAULT_DICTATION_FINAL_TIMEOUT_MS = 10_000, min(DICTATION_FINAL_TIMEOUT_MAX_MS = 5 min, 10 s + 15 s per pending segment + 1.5 s per pending audio second + 250 ms per missing seq))`, emitted in `finish_accepted.timeoutMs`; on expiry `Timed out waiting for final transcription` (retryable). "buffer too small" provider errors after finish are swallowed as empty. Optional debug WAV dump when `isPaseoDictationDebugEnabled()` (`debugRecordingPath` + activity log).
- Partial transcripts: `transcript` events build `partialText` from committed + current segment ids, emitted as `dictation_stream_partial`; `useDictation` stores `partialTranscript` (the composer does not display it live; it is the fallback when `final.text` is empty).

### 4.4 Result handling
`handleStreamingTranscriptionSuccess` -> trimmed `final.text` (else last partial) -> `onTranscript`. Composer `handleDictationTranscript` (`input.tsx:1486`) -> `applyDictationTranscript` (`state.ts:70`): appends to the current text with a space pad unless it ends in whitespace; **Insert** only replaces the text; **Insert and send** (`sendAfterTranscriptRef` set by `markTranscriptForSend`) either queues (when default behaviour is queue and agent running and `onQueue`) or submits with `forceSend` when the agent is running. Empty transcript = nothing.
Failure: if segments exist -> `status "failed"` + `onPermanentFailure`; overlay offers Retry (`retryFailedDictation`: `resetStreamForReplay` then finish again with the same segments, needs a connection) or Discard; with no segments status returns to idle. Errors toast via `handleDictationError`. `reportError` ignores `AttemptCancelledError`. Action gates (`starting|confirming|cancelling`) prevent double clicks; `AttemptGuard` cancels a stale confirm.

### 6.8 Assistant file links

Target `InlinePathTarget {raw, path, lineStart?, lineEnd?}`. Recognizes `file://` URLs (with `#L10-L20`, `#L3C5`), absolute paths with `:line`, `:line:col`, `:a-b`, `(line,col)`, `... line N`/`lines a-b` suffixes, Windows drive/UNC paths, workspace-relative paths (needs `workspaceRoot`; authored links resolve against `relativePathBase`), `~/` paths. Hover prefetches the lookup (`queryClient.prefetchQuery`, `staleTime: Infinity`, `retry 0`); press opens. `resolveMissingNestedRelativeFile` repairs a link like `workspaceRoot/schema/x.md` to the unique suffix match when the exact path is missing. Tooltip text via `formatFileLinkTooltipPath` (`rel/path:10-20`).
- Open (`provider.tsx` + `path-open.ts`): `AssistantFileLinkResolverProvider` supplies `{client, serverId, workspaceRoot, relativePathBase, onOpenWorkspaceFile(target, disposition), toast}` through a ref context; `dispatchFileTarget`/`dispatchExternalUrl` drop the result if the server/workspace changed while resolving. `createInlinePathOpener` decides file vs directory using `client.listDirectory` (a bare path that lists as a directory opens the Files panel directory; outside-workspace directories open an outside-directory view; anything with a line number is a file), cancel-by-generation, then `normalizeWorkspaceFileLocation` and `openFile(location, disposition)` (`OpenFileDisposition` "preferred" and others; side-pane preferences `openInSidePane.chatFiles`). External http(s) links go to `openExternalUrl`.
- Connections: used by markdown renderers (`app:components/markdown/*`) and chat tool-call views; file panels honour `filePanelAssociations` settings.

### 6.9 Assistant images

### 7.1 What the user sees
- Audio-lines "Voice mode" button in the right slot (`ComposerVoiceModeButton` `index.tsx:1172`): visible only when `mode.showVoice`, the agent exists, the agent is **not running**, voice is not already active for this agent, and (compact) there is no sendable content. Tooltip `composer.voice.voiceMode` + `voice-toggle` chord; spinner while `isVoiceSwitching`. Starting while the agent runs toasts `composer.voice.interruptBeforeVoice`.
- Active: the input surface is replaced by `RealtimeVoiceOverlay` (`app:components/realtime-voice-overlay.tsx`): horizontal `VolumeMeter` (volume + speaking state from `useVoiceTelemetry`), Mute/Unmute (`realtimeVoice.actions.mute|unmute`, red when muted) and Stop (square, red; spinner while switching). The mic button in the input row becomes mute toggle; `Space` (focusScope other) and `Cmd/Ctrl+Shift+D` act too. Stop while the agent is mid-turn first cancels the agent (`stopRealtimeVoice` `state.ts:~245` -> `client.cancelAgent`, then `voice.stopVoice()`).
- Settings: Settings > Voice (4.5): voice mode is **off by default** ("Voice mode is off. Turn it on in Settings > Voice.").

### 7.2 Client runtime (`app:voice/voice-runtime.ts`, provider `app:contexts/voice-context.tsx`)
- `VoiceProvider` creates one `AudioEngine` (`createAudioEngine`) and one `VoiceRuntime` per app; engine capture PCM -> `runtime.handleCapturePcm`; volume -> `handleCaptureVolume`; an OS audio interruption stops voice; `expo-keep-awake` held with tag `"paseo:voice"` while active. Each connected host registers a `VoiceSessionAdapter` (`app:contexts/session-context.tsx:313`: `setVoiceMode`, `sendVoiceAudioChunk`, `audioPlayed`, `abortRequest`, `setAssistantAudioPlaying`).
- Snapshot `{phase: disabled|starting|listening|submitting|waiting|playing|stopping, isVoiceMode, isVoiceSwitching, isMuted, activeServerId, activeAgentId}` and telemetry `{volume, isSpeaking, segmentDuration}` (display volume smoothed: attack 0.35 / release 0.18, publish every `DISPLAY_VOLUME_PUBLISH_INTERVAL_MS = 120` or change >= 0.02).
- `startVoice(serverId, agentId)`: requires registered+connected session; `resolveVoiceUnavailableMessage(serverInfo,"voice")` else throws; if switching hosts/agents first disables the previous one; keep-awake; `engine.initialize()`; `adapter.setVoiceMode(true, agentId)` (server enables voice and reloads the agent session with a voice system prompt); `engine.startCapture()`; sets phase `listening`; failures disable voice mode and tear down. `stopVoice()`: stops cue/uploader/playback, `setVoiceMode(false)`, `stopCapture`, releases keep-awake. On reconnect `resyncVoiceMode` re-sends `set_voice_mode(true)`.
- Capture upload: PCM chunks base64'd as `audio/pcm;rate=16000;bits=16` via `voice_audio_chunk {audio, format, isLast:false}` (only while `transportReady`, voice mode on and not muted; mute resets telemetry and stops sending).
- Playback: `audio_output {audio, format, id, isVoiceMode, groupId?, chunkIndex?, isLastChunk?}` is routed to `runtime.handleAudioOutput` when `isVoiceMode` (grouped per `groupId` = one spoken utterance, chunks ordered by `chunkIndex`, played through the engine queue, each chunk acknowledged with `audio_played {id}` after it finishes or fails); non-voice-mode audio (`isVoiceMode:false`) is buffered per group and played once complete (`app:contexts/session-context.tsx:568`). `onAssistantAudioStarted/Finished` flip phase `playing` and `setAssistantAudioPlaying`.
- Barge-in: server `voice_input_state {isSpeaking:true}` -> `onServerSpeechStateChanged`: resets playback state, stops the engine and clears its queue, drops the cue; the server aborts TTS and the agent run on speech start.
- Thinking cue: while phase `waiting` and the user is not speaking, an audio cue (`THINKING_TONE_NATIVE_PCM_BASE64` asset) starts after `THINKING_TONE_MIN_SILENCE_MS = 1500` and repeats every duration + `THINKING_TONE_REPEAT_GAP_MS = 350`.
- Phase driven by `transcription_result` (non-empty -> `waiting`, empty -> back to `listening`), `turn_started`/`turn_completed|failed|canceled` events (`onTurnEvent`), playback start/finish.
- VAD constants (client): `REALTIME_VOICE_VAD_CONFIG` (`app:voice/realtime-voice-config.ts`: `volumeThreshold 0.12`, `confirmedDropGracePeriodMs 1000`, `silenceDurationMs 2000`, `speechConfirmationMs 120`, `detectionGracePeriodMs 700`, `interruptGracePeriodMs 1000`); I found no consumer in the current runtime (turn detection is server-side Silero VAD), treat as dormant config. Not found: `grep REALTIME_VOICE_VAD_CONFIG app:` consumers outside tests.

### 7.3 Server side (`srv:session/voice/voice-session.ts`)
- `set_voice_mode {enabled, agentId?, requestId?}` -> `handleSetVoiceMode` (`:354`): enable checks readiness (`resolveVoiceFeatureUnavailableContext("voice_mode")` -> `VoiceFeatureUnavailableError` with `reasonCode/retryable/missingModelIds`), requires a UUID `agentId` (`AgentIdSchema = z.guid()`), disables a previous voice agent, then `enableVoiceModeForAgent`: loads the agent, registers the **speak tool handler** and caller context (`enableVoiceTools:true`) for that agent in the MCP voice bridge, strips/rebuilds the system prompt block `<paseo_voice_mode>...</paseo_voice_mode>` (`buildVoiceModeSystemPrompt`, `srv:voice-config.ts`: instructions to always use the `speak` tool, acknowledge before tools, concise speech) and **reloads the agent session** with it; starts `VoiceTurnController` (`voice-turn-controller.ts`: Silero VAD + streaming STT; final transcript timeout `VOICE_FINAL_TRANSCRIPT_TIMEOUT_MS = 10_000`). Disable restores the system prompt (a "voice mode is now off" block) and unregisters handlers. Response `set_voice_mode_response {requestId, enabled, agentId, accepted, error, reasonCode?, retryable?, missingModelIds?}`; client throws `error (reasonCode)` when `accepted` is false.
- Inbound `voice_audio_chunk`: in voice mode forwarded to the turn controller (`appendClientChunk`); outside voice mode, audio is buffered per format (PCM wrapped into WAV at 16 kHz mono 16-bit; streaming threshold `MIN_STREAMING_SEGMENT_DURATION_MS = 1000`), transcribed by `STTManager`, a `transcription_result` is emitted but no agent turn runs.
- VAD callbacks: speech start emits `voice_input_state {isSpeaking:true}`, aborts playback/agent (`handleVoiceSpeechStart` -> `handleAbort`), drops buffered segments; speech stop sets phase `transcribing` and logs an activity "Transcribing audio..."; final transcript -> `transcription_result {text, language?, duration?, requestId, avgLogprob?, isLowConfidence?, byteLength?, format?, debugRecordingPath?}`; **low-confidence results are blanked** (`isLowConfidence` -> ignored as non-speech); non-empty transcript -> `host.sendSpokenInput(agentId, text)` which wraps it with `wrapSpokenInput` (`<spoken-input>...</spoken-input><instruction>... respond using the speak tool only ...</instruction>`) and goes through `handleSendAgentMessage` -> same send path as typed text (2.2 step 7, `clearPendingPermissions`).
- Agent speech: the MCP `speak` tool handler calls `TTSManager.generateAndWaitForPlayback(text, emit, abortSignal, true)` (`srv:agent/tts-manager.ts`): text normalized and split per sentence, oversized fragments split by clauses/words with `MAX_TTS_SEGMENT_CHARS = 260`, `TTS_PREFETCH_SEGMENTS = 2`; each segment streamed as `audio_output` chunks; playback completion tracked by `audio_played` ids (recently closed ids remembered `CLOSED_AUDIO_ID_TTL_MS = 10_000`); an assistant activity entry is logged. `abort_request` aborts the signal, cancels pending playbacks, and interrupts the voice agent if running (`interruptAgentIfRunning`; failure emits an `activity_log` error with `metadata.voiceAbortFailed`, which the app surfaces as a toast via `notifyVoiceAbortFailure`).
- Session idle accounting: `hasDemand` keeps speech services warm while voice mode/dictation/buffers are active.

### 7.4 Audio engines and `expo-two-way-audio`
- `createAudioEngine` (`app:audio/audio-engine.{web,native}.ts`, interface `audio-engine-types.ts`: `initialize/destroy/startCapture/stopCapture/toggleMute/isMuted/play/stop/clearQueue/isPlaying`). Shared `createPlaybackQueue` (`app:audio/playback.ts`: FIFO, per-item `AbortController`, `stop()` aborts the active item, `clearQueue()` rejects pending with "Playback stopped", `onIdle` callback). Errors in playback reject with "Playback stopped" on abort.
- Web: playback via `AudioContext` (`ensurePlaybackContext` resumes a suspended context with a 2 s timeout -> "Audio playback requires a user interaction"), PCM (`audio/pcm;rate=N`, default 24000) converted to an `AudioBuffer`, other formats via `decodeAudioData`; capture = `getUserMedia({channelCount:1, noiseSuppression, echoCancellation, autoGainControl})` + `ScriptProcessor(4096)` + resample to 16 kHz PCM16, volume `min(1, rms*2)`; mute drops PCM but keeps volume meter. Needs HTTPS or localhost (except Electron).
- Native: `@getpaseo/expo-two-way-audio` (`packages/expo-two-way-audio`): JS API `initialize, playPCMData, bypassVoiceProcessing, toggleRecording, startDictation (falls back to toggleRecording on old binaries), isRecording, releaseAudioSession (no-op on old binaries), tearDown, restart, get/requestMicrophonePermissionsAsync, get/setMicrophoneModeIOS, isPlaying, stopPlayback, pausePlayback, resumePlayback`; events `onMicrophoneData {data: Uint8Array}`, `onInputVolumeLevelData`, `onOutputVolumeLevelData`, `onRecordingChange`, `onAudioInterruption {data: "blocked"|"capture_paused"|"capture_resumed"}`. Both platforms capture and play **16 kHz mono PCM16** with acoustic echo cancellation. iOS (`ios/AudioEngine.swift`): `AVAudioSession` `.playAndRecord` / `.voiceChat` with `defaultToSpeaker, allowBluetooth, allowBluetoothA2DP`, voice-processing IO on the input node, tap buffer 2048 frames, interruption/media-reset observers, `releaseAudioSession` deactivates with `notifyOthersOnDeactivation` and resets category to `.ambient + mixWithOthers` so other apps' audio resumes. Android (`android/.../AudioEngine.kt`): `AudioRecord` (16 kHz) + `AcousticEchoCanceler` + `NoiseSuppressor`, `AudioTrack` `USAGE_VOICE_COMMUNICATION` `MODE_STREAM`, audio focus `AUDIOFOCUS_GAIN_TRANSIENT_EXCLUSIVE` (lost focus emits `blocked`; dictation keeps its `AudioRecord` and only reports capture paused/resumed). Native engine behaviours: capture `blocked` -> engine clears `captureActive`/mute and calls `onInterruption`; PCM playback resampled from the chunk's rate to 16 kHz (`playPcm16`, `app:audio/pcm/index.ts`) using the native engine (shares the echo reference); non-PCM audio (WAV/MP3...) is written to a cache file and played with `expo-audio` (`allowsRecording:false`, duck others, `playFile` with load timeout 15 s and playback timeout duration + 30 s); the OS session is released as soon as capture and playback are both idle (`releaseSessionIfIdle`). Permission failure message "Microphone permission is required to capture audio...".
- Plugin audio playback: `createPlayAudio(engine, signal)` (`app:audio/play-audio.ts`): RPC-friendly `{base64, mimeType}` (validates base64 shape and an `audio/*` MIME, **rejects raw `audio/pcm`**) -> `engine.play` (used by plugin runtime, other area).
- Capability/permission gate: voice mode needs `capabilities.voice.voice.enabled` (daemon readiness incl. turn detection + STT + TTS models), dictation only needs `capabilities.voice.dictation.enabled`.

## 9. Key facts about permissions and ordering that affect porting
- Pending permission rule (2.1): `"queue"` behaviour degrades to interrupt when a permission is pending; the server answers/denies the permission when a human message arrives (`clearPendingPermissions: true`).
- Optimistic user message + `clientMessageId` + server-side `MessageReceipts` dedup is the contract that makes retried sends idempotent (same `messageId` + different payload = `agent_request_key_conflict`).
- Queued messages never touch the daemon; only the first is sent as `steer` when the agent goes idle.
- Image bytes are base64 inside the `send_agent_message_request` JSON frame (no size cap found; searched `proto:messages.ts` `ImageAttachmentSchema` and `srv:` send handler); only generic files are capped (50 MB client-side) and use binary frames.
