# p3 - Pull requests / forge and review (Paseo 0.15.4)

Source root: `~/refs/paseo-latest/packages`. Paths below are relative to it unless absolute.
Abbreviations: APP = `app/src`, SRV = `server/src`, SVC = `server/src/services`, PROTO = `protocol/src`, CLIENT = `client/src/daemon-client.ts`.

Key architecture fact: the daemon shells out to forge CLIs (`gh`, `glab`, `tea`) for everything; there is no direct REST/OAuth client in Paseo. The app never talks to a forge; it only sees the neutral wire shapes ("change request" = PR/MR). `checkout_pull_request` is NOT "checkout a PR" -- it is `git pull` (see the Pull/Push section).

## Forge manifest and forge resolution (which forge backs a workspace)

### What the user sees
- Brand label/icon/noun per workspace: "PR" vs "MR", `#123` vs `!123`, "Open on GitLab", GitHub/GitLab/Gitea/Forgejo/Codeberg marks. Unknown forge ids render neutral ("PR", `#`, generic GitPullRequest glyph), never GitHub-branded (`PROTO/forge-manifest.ts` `getForgeDefinitionOrNeutral`).
- Sign-in hint when a forge is unauthenticated ("gh auth login", "glab auth login --hostname <host>", "tea login add"): `APP/git/forge.ts:112` `buildForgeSignInCommand`.

### Manifest (build-time data, never on the wire)
`PROTO/forge-manifest.ts` `FORGE_DEFINITIONS` (id, displayName, changeRequestAbbrev, changeRequestNoun, changeRequestNumberPrefix, issueNumberPrefix, iconKind, signIn{cli,command,hostnameFlag?}, cloudHosts?):
| id | name | abbrev/noun | prefix | signIn | cloudHosts |
|---|---|---|---|---|---|
| github | GitHub | PR / pull request | # | `gh`, `gh auth login` | github.com, ssh.github.com |
| gitlab | GitLab | MR / merge request | ! | `glab`, `glab auth login`, hostnameFlag `--hostname` | gitlab.com |
| gitea | Gitea | PR | # | `tea`, `tea login add` | gitea.com |
| forgejo | Forgejo | PR | # | `tea login add` | none (probe only) |
| codeberg | Codeberg | PR | # | `tea login add` | codeberg.org |
`DEV_FORGE_DEFINITIONS = []`. `getForgeDefinitionOrNeutral(id)` synthesizes {abbrev "PR", noun "pull request", prefix "#", iconKind "git", signIn null}.
Other shared leaf files: `PROTO/check-traits.ts` (`CHECK_TRAIT_MANUAL="manual"`, `CHECK_TRAIT_ACTION_REQUIRED="action_required"`, `CHECK_TRAIT_WARNING="warning"`; open set, unknown traits ignored), `PROTO/gitea-status.ts` (`mapGiteaCommitState`: success->success; failure|error|warning->failure; skipped->skipped; else pending), `PROTO/gitlab-pipeline.ts` (`GITLAB_ACTIVE_PIPELINE_STATUSES` = created, waiting_for_resource, preparing, pending, running, canceling, scheduled), `PROTO/git-remote.ts` (`parseGitRemoteLocation(url)` -> {host,path,transport: ssh|scp|http|https,port}, `normalizeHost`).

### Server resolution
- `SVC/forge-registry.ts` `ForgeRegistry` (id regex `^[a-z0-9][a-z0-9._-]*$`, register/ids/has/create/matchHost/probeHost). `defaultForgeRegistry` entries: github (createGitHubService, matchesHost from manifest cloudHosts, probeHost `probeGitHubHost` = GHES), gitlab (createGitLabService, cloud match, `probeGitLabHost`), gitea (createGiteaService, cloud match, probe `resolveGiteaFamilyForge(host)==="gitea"`), forgejo (createGiteaService, probe `==="forgejo"`), codeberg (createGiteaService, cloud match only). Two adapters claiming one host -> warn once, resolve to null. `probeHost` uses `Promise.allSettled` (a throwing probe = "not this forge").
- `SVC/forge-resolver.ts` `createForgeResolver()`: `resolve(cwd)` reads `git config --get remote.origin.url` (`defaultResolveRemoteUrl` in `SVC/forge-cli-command.ts`), memoized per cwd for `NEGATIVE_PROBE_TTL_MS=60_000`; `resolveFromRemoteUrl` (sync: cloud-host match or cached probe) and `resolveFromRemoteUrlAsync` (cloud match, then for ssh/scp remotes `ssh -G` hostname resolution via `utils/ssh-hostname.ts`, then per-host probe). Positive probe cached forever, negative 60 s (`NEGATIVE_PROBE_TTL_MS`); LRU cap `FORGE_RESOLVER_CACHE_MAX=512`; concurrent probes of a host coalesced; SSH alias also cached under the alias host. One adapter instance per forge id (`services` map). `invalidate(cwd)` drops cwd cache and calls every adapter's `invalidate({cwd})`.
- Self-hosted detection is CLI-driven: `probeHostViaCliAuthStatus({cli, host})` runs `<cli> auth status --hostname <host>` with `CLI_AUTH_PROBE_TIMEOUT_MS=10_000`; no anonymous HTTP fallback (a remote host is trusted only when the CLI already knows it). Gitea family additionally probes `/api/forgejo/v1/version` (`FORGEJO_VERSION_PATH`, `GITEA_SOFTWARE_PROBE_TIMEOUT_MS=5_000`) and `tea login list -o json` to split gitea vs forgejo.
- Workspace entry points: `WorkspaceGitService.resolveForge(cwd)` (`SRV/server/workspace-git-service.ts:650`) wraps the resolver; `forgeOverrides` dep lets tests inject adapters. If no forge resolves, worktree creation falls back to GitHub (`SRV/server/worktree-core.ts:220` `resolveForge`) unless the checkout source names a non-github forge (-> `UnsupportedForgeCheckoutTargetError`).

### App-side forge modules (client)
- `APP/git/forge.ts`: `normalizeForge(raw)` -> raw or `"github"` for null/empty (old daemons never sent `forge`); `forgeFromRemoteUrl(remoteUrl)` matches only manifest cloudHosts (self-hosted unresolved -> null); `getForgePresentation(forge)` -> {forge, icon, brandLabel, changeRequestAbbrev, changeRequestNoun, numberPrefix, issueNumberPrefix, signInCli, changeRequestContext: "mr"|undefined (i18next context -> `_mr` string variants), buildBlobUrl, buildBranchTreeUrl}; `parseForgeAuthState(value)` accepts only the five `ForgeAuthState` literals.
- `APP/git/client-forge-module.ts`: split into logic modules (`ClientForgeLogicModule` {id, urlGrammar?, facts?}) and view modules (`ClientForgeViewModule` {id, icon, brandColor?{light,dark}, paneContributions?}) so Node e2e harnesses avoid the RN stack. Registries: `APP/git/forges/index.ts` `CLIENT_FORGE_LOGIC_MODULES` = [github, gitlab, gitea, forgejo, codeberg]; `APP/git/forges/view.ts` `CLIENT_FORGE_VIEW_MODULES` (same order). Facts API: `defineForgeFacts({family, schema(zod), deriveMergeCapability?, nativeFallbackChecks?})`, `defineNativeFallbackCheck`, `definePaneContribution`. `parseClientForgeFacts(facts)` tries every module's schema.
- URL grammar per forge (`ForgeUrlGrammar`: treeInfix, blobInfix, lineAnchor, changeRequestChecksSuffix?, referencePaths[]):
  - github: `/tree/`, `/blob/`, `#L1-L5`, checks suffix `/checks`, refs `/pull/` (change_request), `/issues/`.
  - gitlab: `/-/tree/`, `/-/blob/`, `#L1-5`, checks suffix `/pipelines`, refs `/-/merge_requests/`, `/-/issues/`.
  - gitea/forgejo/codeberg (`GITEA_FAMILY_URL_GRAMMAR`): `/src/branch/` for both, `#L1-L5`, refs `/pulls/`, `/issues/`; no checks suffix.
- `APP/git/forge-url.ts`: `buildForgeChecksUrl(forge, changeRequestUrl)` (http/https only), `buildForgeBranchTreeUrl`, `buildForgeBlobUrl` ("Open on <forge>" from the workspace remote; self-hosted host used as-is plus non-default port only for http(s) remotes; cloud SSH alias canonicalized to `cloudHosts[0]`; path segments normalized, `..` rejected; branch `HEAD` -> null), `hasForgeWebUrls`.
- `APP/git/forge-refs.ts`: `extractForgeRefs(text, remoteUrl)` / `parseForgeRef` scan pasted http(s) URLs (strip trailing `.,;:!`) for change-request/issue links of THIS repository only (`/<repoPath><infix><n>`, case-insensitive prefix, positive safe int). Used by composer auto-attach.
- `APP/git/forge-icon.tsx`: `getForgeIconComponent(iconKind)`, `getForgeBrandColorMapping`, `ForgeBrandIcon`; fallback lucide `GitPullRequest`. `APP/git/forges/{github,gitlab,gitea,forgejo,codeberg}.view.tsx` supply the marks (gitlab.view.tsx also has the pipeline/approvals pane contribution).
- `APP/git/pull-request-state-icon.tsx`: open=GitPullRequest (statusSuccess), merged=GitMerge (statusMerged), closed=GitPullRequestClosed (statusDanger).

Reads: workspace remote URL (checkout status), `serverInfo.features`. Feeds: PR status (below), search, worktree-from-PR, composer attachments, new-workspace picker.

## Server forge adapter contract (`ForgeService`)

`SVC/forge-service.ts` interface (the Rust port target); all methods are CLI-backed:
- Reads: `listPullRequests({cwd,query?,limit?})`, `listIssues`, `getPullRequest({cwd,number})` -> `PullRequestSummary{number,title,url,state,body,projectPath?,baseRefName,headRefName,labels[],updatedAt}`, `getPullRequestHeadRef`, `getPullRequestCheckoutTarget` -> `PullRequestCheckoutTarget{number,baseRefName,headRefName,checkoutRefs?[{remoteName?,remoteRef}],headOwnerLogin,headRepositorySshUrl,headRepositoryUrl,isCrossRepository,headRefKind?: "branch"|"pull-ref"}`, `getCurrentPullRequestStatus({cwd,headRef,headSha?,headRepositoryOwner?})` -> `CurrentPullRequestStatus|null`, `getPullRequestTimeline({cwd,prNumber,repoOwner,repoName})`, `getCheckDetails({cwd,repoOwner?,repoName?,checkRunId?,workflowRunId?,changeRequestNumber?})`, `searchIssuesAndPrs({cwd,query,limit?,kinds?})`, `isAuthenticated({cwd})`.
- Writes: `createPullRequest({cwd,title,head,base,body?})` -> {url,number}; `mergePullRequest({cwd,prNumber,mergeMethod: merge|squash|rebase,status?})`; `enablePullRequestAutoMerge(...)`; `disablePullRequestAutoMerge(...)`.
- Optional hooks: `defaultCheckoutRefs({changeRequestNumber,headRef})`, `buildPrLocalBranchName({headRef,checkoutTarget})`, `supportsCrossRepoCheckoutWithoutRefs` (github true), `authProbeCanThrow` (github true: isAuthenticated rejects with classified `ForgeCliMissingError`/`ForgeAuthenticationError`; GitLab/Gitea resolve false), `retainCurrentPullRequestStatusPoll({cwd,headRef,headSha?,headRepositoryOwner?,onStatus,onError})` -> `{unsubscribe}` (github only), `invalidate({cwd})`, `dispose()`.
- `ForgeReadOptions` = `{force?:false,reason?}` | `{force:true, reason:string}` (forced reads require a reason string, used for logging: "merge-pr-validation", "auto-merge-validation", "manual-refresh").
- Types: `ForgeAuthState` = authenticated | unauthenticated | cli_missing | no_remote | error (no_remote also = no branch to look up; error = non-auth failure, UI shows the real error). `PullRequestCheck{name,status: pending|success|failure|cancelled|skipped,url|null,workflow?,duration? (formatted string),checkRunId?,workflowRunId?,traits?[]}`. `computeChecksStatus`: none if empty; failure if any failure; pending if any pending; else success. `PullRequestMergeable` MERGEABLE|CONFLICTING|UNKNOWN. `PullRequestReviewDecision` approved|changes_requested|pending|null. `CurrentPullRequestStatus{number?,repoOwner?,repoName?,projectPath?,url,title,state,baseRefName,headRefName,isMerged,isDraft?,mergeable,checks[],checksStatus,reviewDecision,forgeSpecific?}` where `forgeSpecific` = `{forge: <facts family>} & facts` (see facts below).
- Timeline: `PullRequestTimelineItem` = review{id,author,authorUrl,avatarUrl,body,createdAt(ms),url,reviewState approved|changes_requested|commented} | comment{... , reviewId?,threadId?,threadIsResolved?,location?{path,line?,startLine?,threadId?,isResolved?,isOutdated?}}; `PullRequestTimeline{prNumber,repoOwner,repoName,items,truncated,error: {kind: not_found|forbidden|unknown, message}|null}`; stable order `compareTimelineItems` (createdAt, then id).
- Check details: `CheckDetails{checkRunId,workflowRunId?,name,status?,conclusion?,url?,detailsUrl?,output?{title,summary,text},annotations[{path,startLine,endLine,annotationLevel,message,title,rawDetails}],failedJobs[{jobId,name,status,conclusion,url,completedAt?,logTail?,logTruncated?}],truncated,pipeline?}` and GitLab `PipelineDetails{id,status,rawStatus,url,ref,sha,stages[{name,status,jobs[{id,name,stage,status,rawStatus,url,allowFailure,durationSeconds}]}]}`; `PipelineJobStatus` = success|failed|running|pending|canceled|skipped|manual|created|unknown.
- Search: `normalizeForgeSearchKinds(kinds)`: default `["issue","change_request"]`; legacy aliases `github-issue`->issue, `github-pr`|`pr`->change_request. `SearchResult{items[{kind,forge?,number,title,url,state,body,labels,projectPath?,baseRefName?,headRefName?,updatedAt?}],featuresEnabled,authState,githubFeaturesEnabled?}`; `createUnavailableSearchResult(authState)`.
- Shared CLI plumbing `SVC/forge-cli-command.ts` `createForgeCliRunner({binary,envOverlay,timeoutMs,isAuthFailureText,errorClasses})`: exec with `maxBuffer 10 MB`, per-call env overlay, timeout; error normalization: ENOENT -> missing-CLI error; auth-failure text -> auth error; `killed` + timeout -> command error "terminated before completing (timed out after Nms or exceeded the output limit)"; others -> `ForgeCommandError{args,cwd,exitCode,stderr,stdout?}`. `createCachedCliPathResolver` caches a found CLI path forever, a miss is retried next call. `parseCliJsonOutput` validates with zod.

## Per-adapter behavior (GitHub, GitLab, Gitea family)

### GitHub (`SVC/github-service.ts`, `gh` CLI)
- Env `GIT_TERMINAL_PROMPT=0`; command timeout `GITHUB_COMMAND_TIMEOUT_MS=30_000`; response cache `DEFAULT_GITHUB_CACHE_TTL_MS=30_000` keyed by cwd+method+stable-JSON args (forced reads bypass; an in-flight non-forced request is shared; forced read without `reason` throws "ForgeService forced read requires a reason"); repo-host / slug null cache `REPO_HOST_NULL_TTL_MS=60_000`; origin URL read timeout `GIT_ORIGIN_URL_READ_TIMEOUT_MS=5_000`.
- Commands: list PRs `gh pr list --search <q> --json number,title,url,state,body,labels,baseRefName,headRefName,updatedAt --limit <limit default 20>`; list issues `gh issue list --search ... --json number,title,url,state,body,labels,updatedAt`; view `gh pr view <n> --json ...`; checkout target = GraphQL `PULL_REQUEST_CHECKOUT_TARGET_QUERY` + fork PR lookups (`FORK_PR_VIEW_LIMIT=3`, `FORK_PR_PAGE_SIZE=100`); current status = `gh pr view`/`gh pr list --state all --head <ref> --limit 10` + GraphQL facts query (`PULL_REQUEST_STATUS_FACTS_QUERY`); timeline = `gh api graphql` with reviews(first:100), comments(first:100), reviewThreads(first:100){comments(first:100)} and pageInfo (-> `truncated`); body images normalized (`normalizeGitHubTimelineBody`, GitHub rendered-image hosts); check run = `gh api repos/<o>/<r>/check-runs/<id>` + annotations (`CHECK_ANNOTATION_PAGE_MAX=20`) + Actions jobs (`ACTIONS_JOB_PAGE_MAX=100`, `FAILED_CHECK_JOB_LIMIT=5`) + job logs `gh api repos/.../actions/jobs/<id>/logs` capped to `CHECK_LOG_TAIL_MAX_LINES=200` / `CHECK_LOG_TAIL_MAX_BYTES=16*1024` (UTF-8 safe suffix, cache `CHECK_LOG_TAIL_CACHE_MAX_ENTRIES=128`); create PR = `gh api -X POST repos/<slug>/pulls -f title -f head -f base [-f body]` (slug from origin remote offline, fallback `gh repo view --json owner,name,parent`); merge `gh pr merge <n> --<merge|squash|rebase>`; auto-merge `gh pr merge <n> --auto --<method>`; disable `gh pr merge <n> --disable-auto`; auth `gh auth status` (GHES `gh auth status --hostname <host>`); repo list `gh repo list --json id,name,nameWithOwner,description,isPrivate,updatedAt,sshUrl,url --limit N`; repo search `gh search repos <q> --json id,name,fullName,description,isPrivate,updatedAt,url --sort updated --order desc --limit N` (`searchRepositories`, GitHub-only; clone protocol from `gh config get git_protocol`); search = issues + PRs in parallel (`Promise.allSettled`), URL pasted queries normalized (`normalizeGitHubSearchQuery`: github.com or workspace GHES host issue/PR URL -> number).
- `getCheckDetails` requires repoOwner+repoName+checkRunId ("GitHub getCheckDetails requires ...").
- Merge guards (server-side, mirrored by UI policy): direct merge requires `mergeStateStatus` in {CLEAN, HAS_HOOKS}, no merge queue (`isMergeQueueEnabled`/`isInMergeQueue`), `autoMergeRequest===null`, method allowed by repo flags (`isPullRequestMergeMethodAllowed`); enable auto-merge requires `mergeStateStatus==="BLOCKED"`, `viewerCanEnableAutoMerge`, `repository.autoMergeAllowed`, method allowed, no existing auto-merge, no queue, mergeable != CONFLICTING; disable requires auto-merge present + `viewerCanDisableAutoMerge` + no queue. Error strings are user-visible via toast (e.g. "GitHub does not report this pull request as ready for direct merge").
- Status polling (`retainCurrentPullRequestStatusPoll`, ref-counted per {cwd, headRef, headSha, headRepositoryOwner}): fast `GITHUB_POLL_FAST_INTERVAL_MS=20_000` when any check pending else slow `GITHUB_POLL_SLOW_INTERVAL_MS=120_000`; consecutive-error backoff `base*2^(errors-1)` capped `GITHUB_POLL_ERROR_BACKOFF_CAP_MS=300_000` (`computeGithubNextInterval`); polls batched into aliased GraphQL queries `GITHUB_POLL_BATCH_MAX=25` per request, aligned to a shared grid `GITHUB_POLL_ALIGNMENT_MS=5_000`; per-host pause when GraphQL remaining <= limit*`GITHUB_GRAPHQL_RESERVE_RATIO=0.4` until resetAt+`GITHUB_GRAPHQL_RESET_GRACE_MS=1_000` (reset read via `gh api rate_limit`); `BATCH_PR_CANDIDATE_LIMIT=10`; frozen checks cache for merged/closed PRs (`FROZEN_PR_CHECKS_CACHE_MAX_ENTRIES=512`).
- Candidate choice when several PRs share a head branch: `pickPullRequestCandidate` / `comparePullRequestCandidatePreference` (prefers open, then by state rank, head SHA match).

### GitLab (`SVC/gitlab-service.ts`, `glab` CLI)
- `GLAB_COMMAND_TIMEOUT_MS=30_000`; `TIMELINE_PAGE_SIZE=100`. Commands: `glab mr view <ref> -F json`; `glab mr list --all --source-branch <b> --order updated_at --sort desc --per-page 100 -F json` (current MR = first open MR with that source branch, else a non-open MR whose `sha === headSha`); approvals via `glab api projects/<enc path>/merge_requests/<iid>/approvals`; discussions `.../discussions?per_page=100` with a one-item probe at page 101 to detect truncation; pipeline `glab ci get --merge-request <iid> --with-job-details -F json` (older glab: `--pipeline-id`); create `glab mr create --title --description --source-branch --target-branch --yes` (URL extracted from stdout; iid parsed from URL); merge `glab mr merge <n> --auto-merge=false --yes [--squash|--rebase]`; enable auto-merge `glab mr merge <n> --auto-merge --yes [--squash|--rebase]` (only allowed while pipeline active); disable = `glab api --method POST projects/:fullpath/merge_requests/<n>/cancel_merge_when_pipeline_succeeds`; positional args guarded against leading `-` (`assertSafeGlabPositional`). Checkout refs: `refs/merge-requests/<iid>/head` then `refs/heads/<source_branch>`; `isCrossRepository` = source_project_id != target_project_id; `headRefKind: "branch"`.
- Guards: direct merge requires facts, `!mergeWhenPipelineSucceeds`, and ready: `detailedMergeStatus==="mergeable"` or (legacy) `mergeStatus==="can_be_merged"` && !hasConflicts; auto-merge enable requires an active pipeline (`GITLAB_ACTIVE_PIPELINE_STATUSES`) and not already enabled ("GitLab auto-merge requires an in-progress pipeline; ...").
- Host probe `probeGitLabHost` = `glab auth status --hostname <host>`. No retained poll (`retainCurrentPullRequestStatusPoll` absent), the generic poller in WorkspaceGitService is used.

### Gitea / Forgejo / Codeberg (`SVC/gitea-service.ts`, `tea` CLI, one adapter for the family)
- `TEA_COMMAND_TIMEOUT_MS=30_000`; sensitive args redacted in logged errors (`--title`, `--description`, `--body` -> `<redacted>`). `tea pr list --fields index,state,author,url,title,body,mergeable,base,head,created,updated,labels,comments,ci --state <s> -o json`; `tea pr <n> -o json`; `tea api ...` for timeline (issue comments + `pulls/<n>/reviews` + per-review comments; page size `TIMELINE_PAGE_SIZE=50`, `TIMELINE_MAX_PAGES_PER_BUCKET=4`, review-comments fan-out concurrency `REVIEW_COMMENTS_FAN_OUT_CONCURRENCY=5`), commit status `repos/<o>/<r>/commits/<sha>/status`, Gitea Actions tasks (`GITEA_ACTION_PAGE_LIMIT=50`, `GITEA_ACTION_MAX_PAGES=5` = 250 newest tasks); head SHA cache `CURRENT_PR_HEAD_SHA_CACHE_TTL_MS=30_000`; current PR lookup `CURRENT_PR_LOOKUP_PAGE_SIZE=50`, `CURRENT_PR_OPEN_LOOKUP_MAX_PAGES=4`; merge `tea pr merge <n> --style <merge|squash|rebase>` guarded by facts `mergeable && !hasMerged`; auto-merge enable/disable throws "<method> is not supported on Gitea yet" (the app derives `canEnableAutoMerge:false`). AGit PRs (`GITEA_PULL_REQUEST_FLOW_AGIT=1`) report `headRefKind:"pull-ref"`.
- Auth: `isAuthenticated` true iff `tea` resolvable and `tea login list -o json` has a login whose host equals the remote host (never throws; `authProbeCanThrow` unset). Family discrimination via `resolveGiteaFamilyForge(host)` (gitea vs forgejo) using `/api/forgejo/v1/version` probe (`GITEA_SOFTWARE_PROBE_TIMEOUT_MS=5_000`) and login list.
- Auth failure text regex (gitea): `/\b(401|unauthorized|not logged in|authentication failed|no token|invalid token|no logins?)\b/i`.

### Generic PR-status poll (non-GitHub forges)

## Current-branch PR status (sidebar badge, header, Git actions) -- end to end

### What the user sees
- Per-workspace sidebar badge `PrBadge` (`APP/components/sidebar-workspace-list.tsx:297`: state icon + `#N`/`!N`, opens `hint.url` via `openExternalUrl`), meta-row CI indicator (`APP/components/sidebar/workspace-meta-row/check-indicator.tsx` + `check-summary.ts`: passed = check in circle, failed = cross, running = pie filling in quarters `PIE_PIECES=4`, floor of completed/total; failure beats progress; falls back to `checksStatus` when no per-check list), hover card (`APP/components/workspace-hover-card.tsx:97,126` PR badge + checks summary + link to `buildForgeChecksUrl`), sidebar context menu entry "View PR/MR #N" (`sidebar-workspace-menu.tsx:367`).
- Git actions split button (see Merge section) and the PR tab (see PR panel).

### Data path

[{origin, refs/heads/<headRef>}]`; GitHub default refs = `origin refs/pull/N/head` then `upstream refs/pull/N/head` (`utils/change-request-checkout.ts buildPullHeadCheckoutRefs`); local branch name = `buildForkLocalBranchName`: same-repo -> head ref; cross-repo -> `<owner>/<head>` (owner lowercased, validated `^[a-z0-9][a-z0-9_.-]*$`, no `..`/trailing `.`/`.lock`) else `pr-<n>/<head>`; synthetic pull-ref heads -> `pr-<n>`; cross-repo fields `headRepositoryOwner`, `headRepository`, `pushRemoteUrl` (ssh url preferred); `trackOriginHead` when same repo and head is a real branch. Intent kind `"checkout-change-request"` {forge, changeRequestNumber, headRef, baseRefName, checkoutRefs, localBranchName?, trackOriginHead?, + cross-repo fields} (legacy kind `checkout-github-pr` with `githubPrNumber`).
- Worktree creation (`SRV/utils/worktree.ts:1576`): unique local branch name (`resolveUniqueLocalBranchName`), then for each checkout ref `git fetch <remote|origin> +<ref>:refs/heads/<localBranch> --force` (timeout 120 s, accepts exit 0/1/128; first success wins; else error "Unable to fetch change request refs for worktree branch ..."), optional tracking remote fetch, push remote: cross-repo -> remote `paseo-pr-<n>` with `remote.<name>.url`, `remote.<name>.push = HEAD:refs/heads/<headRef>`, `branch.<b>.pushRemote`, tracking fetch refspec; same-repo renamed branch -> `paseo-pr-<n>` pointing at origin push URL (track false). Worktree metadata (`.paseo` metadata v2, `SRV/utils/worktree-metadata.ts`) stores `changeRequestLookupTarget {headRef, headRepositoryOwner?, changeRequestNumber?, localBranchName?}` and `baseRefName`; this hint drives PR status lookup for the workspace (poll target) and is rebound on branch rename (`rebindPaseoWorktreeChangeRequestHint`).
- Response: `create_paseo_worktree_response {workspace|null, error|null, errorCode?, setupTerminalId|null, requestId}`. Plugin hook payload `worktree.create.before` accepts intent kinds `checkout-change-request` (forge, changeRequestNumber, headRepository?) and `checkout-github-pr` (`SRV/server/plugins/lifecycle/index.ts:60-84`).
- Agent MCP tool `workspace create` (`SRV/server/agent/tools/paseo-tools.ts:211-300,1403-1431`): `mode: "branch-off"|"checkout-branch"|"checkout-pr"`, `prNumber`, `forge`; checkout-pr maps to `{action:"checkout", checkoutSource:{kind:"change_request", forge?, number}}`; `branchName/baseBranch/branch` rejected in checkout-pr mode (`PaseoToolInputError`).

## Review: inline diff comments sent to the agent

### What the user sees
In the changes diff (workspace "changes" pane, `APP/git/diff-pane.tsx`, working diff hook `APP/git/use-working-diff.ts`) every reviewable diff line has a gutter "+" button (`InlineReviewAddButton`, `APP/review/surface.tsx:83`, hitSlop `SMALL_ACTION_HIT_SLOP=8`) to add a comment for `{filePath, side: old|new, lineNumber}`. Desktop/wide: inline editor (`InlineReviewEditor`: multiline input auto-focused; Escape cancels; Cmd/Ctrl+Enter saves (web keydown listener; Shift+Enter ignored); Cancel / Save ("Comment") buttons; save disabled if trimmed body empty) and inline threads under the line (`InlineReviewThread`, comment rows with edit (`review-comment-edit-<id>`) and delete (`review-comment-delete-<id>`) icon buttons); compact form factor: `ReviewCommentSheet` bottom sheet (`AdaptiveModalSheet`, snap points `["50%","90%"]`, `testID review-comment-sheet`, title "Review comment", subtitle `<file> · <-|+><line>`, Cancel/Save footer). Floating action "Send feedback (N)" (`ReviewFeedbackAction`, `APP/review/feedback/surface.tsx`, hidden unless diff exists and enabled) sends all comments to an agent; with multiple agent tabs a dropdown "Choose an agent" appears; after sending a success toast "Feedback sent to <recipient>" (recipient = agent tab title, resolved through `WorkspaceTabPresentationResolver`; no jump link).
- Disabled notices (`review.feedback.*`): `no-agents` "Open an agent tab in this workspace to send feedback.", `disconnected` "Connect to the host to send feedback.", `no-context` "Saved comments no longer match this diff.", `failed` "Failed to send feedback. Try again." Sending state "Sending feedback (N)". The prompt text sent to the agent: `review.feedback.prompt` = "Please address this code review."

### State and storage
- `APP/review/store.ts` `useReviewDraftStore` (zustand + persist, AsyncStorage key `@paseo:review-draft-store`, `STORE_VERSION=2`, validated by `SerializedReviewDraftStateSchema` (strict), migrate -> `normalizePersistedState` (invalid persisted data -> `{drafts:{}}`; v1 field `activeModesByScope` dropped)). State `{drafts: Record<draftKey, ReviewDraftComment[]>}`; comment `{id (generateMessageId), filePath, side: old|new, lineNumber (positive int), body, createdAt, updatedAt (ISO with offset)}`. Pure reducers in `APP/review/state.ts` (add/update(body only, bumps updatedAt)/delete/clear).
- Draft key (`buildReviewDraftKey`): `review:server=<enc>:(workspace=<enc workspaceId>|cwd=<enc normalized cwd>):mode=<uncommitted|base|all>:base=<enc baseRef>:ignoreWhitespace=<true|false>` (workspaceId preferred, opaque; cwd trailing slashes trimmed). Comments are therefore per diff mode/base/whitespace setting. Diff mode picker comes from `useWorkingDiff` (`selectUncommitted/selectBase/selectAll`).
- Editor models (`APP/review/editor/index.ts`): one editor per (draftKey, presentation) via `createReviewEditorScope` (`presentation` default "diff"); `start`, `edit`, `setBody`, `cancel`, `save` (trims; ignores empty; writes through `saveReviewDraftComment` which updates if the id still exists else adds), `delete`; observable via `subscribe/getState` (`useSyncExternalStore`); released when no listeners and no open editor. Geometry (`APP/review/geometry.ts`): `INLINE_REVIEW_COMMENT_HEIGHT=72`, `INLINE_REVIEW_EDITOR_HEIGHT=132`, `INLINE_REVIEW_GAP=6`, `INLINE_REVIEW_VERTICAL_PADDING=8`; thread height = comments*72 + editors*132 + gaps*6 + 2*8 (editing an existing comment hides that row); split diff takes max of both sides. `useInlineReviewController` returns compact ? `sheetEditor` : inline `editor`.

### Attachment snapshot
`buildReviewAttachmentSnapshot` (store.ts): for each draft comment find the file in the current diff (`ParsedDiffFile` by path) and the target line in a numbered hunk (`buildNumberedDiffHunks`, match by side's cell lineNumber); drop comments whose line no longer exists (that is what "no-context" means when none remain); `CONTEXT_RADIUS=3` lines each side within the hunk (header lines excluded). Result composer attachment `{kind:"review", reviewDraftKey, commentCount, attachment: ReviewAttachment}` where wire `ReviewAttachmentSchema = {type:"review", mimeType:"application/paseo-review", cwd, mode: uncommitted|base|all, baseRef|null?, comments[{filePath, side, lineNumber, body, context:{hunkHeader, targetLine, lines[]}}]}` and line `{oldLineNumber|null, newLineNumber|null, type: add|remove|context, content}` (`PROTO/messages.ts:1179-1206`).
- Published as a workspace attachment while the diff pane is enabled (`usePublishWorkingDiffAttachment` -> `setWorkspaceAttachments({scopeKey, attachments:[attachment]})`, cleared on unmount), so the composer of any agent tab in the workspace shows it as a removable/openable chip and sends it with the next message; chip removal suppresses it for that composer (`suppressWorkspaceAttachment`); after a message that included it is sent, `clearReviewDraft({key: reviewDraftKey})` (composer/attachments/workspace.tsx:155).

### Send feedback workflow (`APP/review/feedback/index.ts`, `use-feedback.ts`)
- `createReviewFeedbackScope().connect(key, ports)` shares one workflow per draft key across surfaces (phase `idle | choosing | sending{recipient,commentCount} | failed{message}`); `deriveState`: `disabledReason` = `no-agents` (no agent tab in workspace) > `disconnected` > `no-context` (no attachment); `canSend = comments>0 && no disabledReason && phase!=="sending"`.
- Recipients = agent tabs from the workspace layout (`readRecipients`: tabs with `descriptor.target.kind==="agent"`). `press()`: one recipient -> send immediately; several -> `choosing` menu. `send(agentId)`: snapshot sent comments (match by filePath+side+lineNumber+body), phase sending, `dispatchComposerAgentMessage({client, agentId, text: i18n "review.feedback.prompt", attachments:[reviewAttachment], encodeImages: ()=>[], submission: createMessageSubmissionWriter(serverId), activeTurnBehavior, activeTurnId})` where behavior = settings `sendBehavior==="steer" ? "steer" : "interrupt"` and `activeTurnId` = current turn id when steering; on success `clearSentReviewDraftComments` removes only the exact versions sent (comparison by id + updatedAt + body, so edits made during send survive) and shows the success toast; on error phase `failed` with message.
- This is a normal agent message (`send_agent_message`-style via composer path) with a `review` attachment; no dedicated RPC.

### Server rendering for the agent
`SRV/server/agent/prompt-attachments.ts` `case "review"`: text = `Paseo review attachment (<mode>)`, `CWD: <cwd>`, optional `Base: <baseRef>`, then per comment: blank line, `Comment <i>: <filePath>:<side>:<lineNumber>`, body, hunk header, and context lines formatted `<"> " if target else "  "><oldLn padStart 2> <newLn padStart 2> <+|-|space><content>` with `-` for missing line numbers.

### Platforms
Inline editor on desktop/web; bottom sheet on compact; Cmd/Ctrl+Enter shortcut is web/desktop only.

### Connections
Reads: diff query (`checkoutDiff`), workspace layout tabs (agents), settings `sendBehavior`; writes: workspace attachment store, agent message, review draft store; shares composer attachment pipeline with PR context attachments.
