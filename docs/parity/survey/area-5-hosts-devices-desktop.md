# Area 5: hosts, connectivity, devices, desktop app (Paseo 0.15.4)

Source root: `~/refs/paseo-latest/packages`. Abbreviations: S = `server/src/server`, A = `app/src`, D = `desktop/src`, P = `protocol/src`, C = `client/src`, R = `relay/src`.
Conventions: "daemon" = the Node server process; "worker" = the child process the supervisor forks; "host" in the app = a saved daemon profile (`HostProfile`); "connected host" = a daemon-side saved link from daemon A to daemon B (`hosts.json`).
Not found anywhere in the sources (searched `packages/desktop/src`, `packages/app/src`): a system tray / menu-bar item (no `Tray` in code), a device list / device revocation UI (no "devices" store, "pairing invitation" is only a design note in `docs/permissions.md`), syncing app settings or files across hosts (app settings live per device in `@paseo:app-settings`; only the agent/workspace replica cache and connected hosts exist). ## Daemon process model: supervisor + worker
### What the user sees / does
- CLI: `paseo daemon start|run|status|stop|restart|reload|pair|config get/set/unset|set-password` (`cli/src/commands/daemon/index.ts:1-30`; options: `start --timeout <s>` default 600 (`start.ts:10`), `stop --timeout` 15 / `--force` / `--kill-timeout` 3 / `--keep-terminals` (`stop.ts:14-21`), `restart --timeout` 600 / `--kill-terminals` (`restart.ts:25-26`), `pair --relay` (`pair.ts:64`)).
- Desktop app starts/stops its own daemon (see "Desktop built-in daemon").
- App: Settings > Host > Danger zone "Restart daemon" (`A/screens/settings/host-page.tsx:558-715`, rendered from `RemoveHostSection` at `:1242`) and "Update daemon" (`:717-900`, only for non-local hosts, `:386`).
### How it works
- Entry: `server/scripts/supervisor-entrypoint.ts` (acquires PID lock `acquirePidLock(paseoHome, null, {ownerPid})` `:116`, starts lock heartbeat `:128`, runs `supervisor.ts` with `restartOnCrash: true` `:171`, writes `{listen, serverId}` into the lock when the worker reports ready `:174`, clears them on worker exit `:177`).
- `scripts/supervisor.ts`: `fork`s `S/daemon-worker.ts` with stdio `["inherit","pipe","pipe","ipc"]`; sends `{type:"paseo:supervisor-heartbeat"}` every `WORKER_HEARTBEAT_INTERVAL_MS = 1_000`; graceful worker stop deadline `WORKER_TERMINATION_GRACE_MS = 10_000` then process-tree SIGKILL; worker messages: `paseo:ready {listen, serverId}`, `paseo:restart {reason?, keepTerminals}`, `paseo:shutdown {reason, keepTerminals}`. Crash policy (`:441-452`): worker exit with code != 0 or a signal other than SIGTERM => respawn (crash restart keeps terminals); worker exit before first readiness => supervisor exits 1; worker exit 0 without a pending restart => supervisor exits. Logs go to `daemon.log` (rotating, `log.file.rotate.maxSize/maxFiles`).
- Worker (`S/daemon-worker.ts`): `process.title = "Paseo Daemon"`; loads config (`loadConfig`), applies CLI flag overrides `--relay/--no-relay/--relay-use-tls/--no-mcp/--no-inject-mcp` (each marks the matching config path "override controlled", `:101-140`); liveness guard `:278-340`: worker exits (code 0) if IPC disconnects, parent pid changes, or heartbeat older than 3500 ms and supervisor pid dead (checked every 1000 ms). Handles `SIGTERM`/`SIGINT` (`:370-371`) and the `paseo:graceful-shutdown` IPC message.
- Lifecycle intents: client RPCs `restart_server_request` / `shutdown_server_request` (P/messages.ts:1915-1930) => `S/session.ts:2753-2760` => `handleRestartServerRequest` (`:3288`) emits `status` payload `{status:"restart_requested", clientId, reason?, requestId}` then `emitLifecycleIntent({type:"restart", keepTerminals: !killTerminals})`; shutdown emits `{status:"shutdown_requested"}` and intent `{type:"shutdown", keepTerminals}`. Intent => `daemon-worker.ts:222-255` sends `paseo:restart`/`paseo:shutdown` to the supervisor (or self-shutdown if no IPC). Restart reason default `"client_restart_rpc"`, shutdown reason `"client_shutdown_rpc"` (`S/lifecycle-reasons.ts`).
- Terminals: restart keeps terminals unless `killTerminals`; shutdown closes them unless `keepTerminals`; terminals live in a separate terminal-worker process adopted by the next daemon (`features.terminalsSurviveRestart`). `closeLeftoverTerminals` / `reapTerminalWorkers` run on stop (`S/daemon-instance.ts:240-275`).
### States, errors, limits
- Stop errors (`S/daemon-instance.ts`): `DAEMON_REPLACED`, `STOP_NO_GRACEFUL_CHANNEL`, `INVALID_STOP_OPTIONS` (`--force` with `--keep-terminals`), `STOP_NOT_CONFIRMED`; start errors: `DAEMON_START_FAILED` (includes last 30 log lines), `DAEMON_NOT_READY`, `DAEMON_NOT_RUNNING`. Defaults: stop timeout 15 000 ms, kill timeout 3 000 ms, start/ready timeout 600 000 ms (desktop uses 30 000, see below). Windows stop uses the shutdown RPC (`requestShutdown`) because SIGTERM cannot be graceful; POSIX uses SIGTERM to the supervisor pid.
- `getProcessDiagnostics()` (`S/process-diagnostics.ts`): pid, ppid, uptime seconds, memory (rss, heapTotal, heapUsed, external, arrayBuffers).
### Platforms
Windows: stop via RPC or `tree-kill`; terminals never kept on desktop-initiated stops (see desktop section). Linux boot-id check in lock (see PID lock).
### Connections
Shared entities: host/daemon, terminals (terminal worker), agents (`agents.resumeOnStartup` restart recovery: `createRestartRecovery` in `S/bootstrap.ts:1047`, `captureRunningAgents` on stop `:1988`), settings (config.json). Triggered by: CLI, desktop app, app settings, daemon self-update (reason `"daemon_update"`, keepTerminals true).

## PID lock / instance lock (`paseo.pid`)
- File `$PASEO_HOME/paseo.pid` (JSON, schema `pidLockInfoSchema` `S/pid-lock.ts:11-21`): `pid, startedAt, hostname, uid, listen|null, serverId?, desktopManaged?, heartbeat?: true, bootId?`. Created with exclusive flag by `acquirePidLock` (`:226`); stale locks cleared (`clearExistingPidLock`). `desktopManaged` is stamped when `PASEO_DESKTOP_MANAGED=1`.
- Heartbeat: `PID_LOCK_HEARTBEAT_INTERVAL_MS = 30_000` touches file mtime (`startPidLockHeartbeat`). Read retries `PID_LOCK_READ_RETRY_ATTEMPTS = 10` x `PID_LOCK_READ_RETRY_DELAY_MS = 50`.
- Liveness = `isPidLockOwnerRunning`: lock must be written during the current boot (`writtenDuringThisBoot`: Linux `/proc/sys/kernel/random/boot_id` match, else `startedAt` must not precede boot instant minus `BOOT_INSTANT_TOLERANCE_MS = 5_000`) AND `process.kill(pid, 0)` succeeds (EPERM counts alive). Guards against PID reuse after reboot.
- `isSamePidLock` compares pid+startedAt; stop/wait functions refuse to act on a different supervisor ("DAEMON_REPLACED").
- `resolvePaseoHome`: env `PASEO_HOME`, default `~/.paseo` (`S/paseo-home.ts`). Private file helpers: dir mode 0700, file mode 0600, atomic temp+rename writes (`S/private-files.ts`).
- Exports for CLI/desktop without loading the daemon: `S/daemon-instance.ts` (`readDaemonInstance`, `waitForDaemonReady`, `startDaemonInstance`, `stopDaemonInstance`, `daemonLogPath`; package export `@getpaseo/server/daemon-control`).

## Daemon identity: server id, keypair, hostname
- `server-id` file: `srv_` + 9 random bytes base64url, persisted 0600 (`S/server-id.ts`); override env `PASEO_SERVER_ID` (persisted if file absent). Used as the host key everywhere (app `HostProfile.serverId`, relay session id, deep links).
- `daemon-keypair.json` (`S/daemon-keypair.ts`): `{v:2, publicKeyB64, secretKeyB64}`, created on first load via `@getpaseo/relay/e2ee generateKeyPair`; the public key goes into pairing offers and is the Noise static key for relay sessions.
- Hostname shown to clients: `getHostName()` (`S/host-name.ts`): macOS `scutil --get ComputerName`, else `os.hostname()`. Sent in `server_info.hostname` and `/api/status`.
- Daemon version: `resolveDaemonVersion` reads `@getpaseo/server` package.json (`S/daemon-version.ts`), in `server_info.version`.

## Authentication, local credential, admission, permissions
### What the user sees / does
- No password set (default): any client that can reach the socket is "owner". Set with `paseo daemon set-password` or env `PASEO_PASSWORD`. In the app a password is entered when adding a host (Direct connection modal "Password", Remote SSH "Daemon password", pairing link prompt `pairing.hostPassword.title/label`) and stored on the profile (`HostProfile.password`); failures show `settings.host.password.guidance` under the connection error (`host-page.tsx:231-249`).
### How it works
- HTTP: `createRequireBearerMiddleware` (`S/auth.ts:99`): when a password hash is configured, every route needs `Authorization: Bearer <password>` (bcrypt compare) except `OPTIONS`, `/api/health`, `/api/files/download` (token query), `/mcp/agents` (capability token or password, `isAgentMcpRequestAuthorized`). `/api/status` (JSON `{status:"server_info", serverId, hostname, version, listen}`, `bootstrap.ts:859`) also accepts the local credential.
- WebSocket: password via HTTP bearer header or subprotocol `paseo.bearer.<token>` (COMPAT headerAuth, `extractWsBearerProtocol`), or in the first `hello` message `auth: {kind:"password", password}` | `{kind:"localCredential", token}` (P/messages.ts `WSHelloMessageSchema` :7741). Resolution in `S/session-admission-auth.ts`: no hash => owner admitted; no credential => reject `password_required`; wrong => `incorrect_password`. Rejection is sent as `hello.rejected {reason: "password_required"|"incorrect_password"|"incompatible_protocol", accepts:["password"]}` when the client set `hello.auth` or `capabilities.helloRejection`; otherwise close code `4401` (`WS_CLOSE_DAEMON_AUTH_FAILED`). Other close codes: `4001` hello timeout (`HELLO_TIMEOUT_MS = 15_000`), `4002` invalid hello, `4003` incompatible protocol (`protocolVersion < 1`, `WS_PROTOCOL_VERSION = 1`), `1001` server shutdown, `1008` invalid host routing frame.
- Local credential: file `$PASEO_HOME/local-credential` (43-char base64url of 32 random bytes, mode 0600), written at daemon start (`writeLocalCredential` in `bootstrap.start()` `:1740`) and deleted on stop or failed start. Lets the desktop app talk to its own password-protected daemon without storing the password: desktop IPC `desktop_local_credential {listen}` (`D/daemon/daemon-manager.ts`) returns it only if the running daemon is `desktopManaged` and the lock `listen` matches the requested target (`readLocalCredentialForTarget`); app `DaemonClient` config `localCredential: () => readDesktopManagedLocalCredential(connection)` (`A/runtime/host-runtime.ts:~570`; `A/desktop/daemon/local-credential.ts`).
- Permissions model (`P/messages.ts:147-158`): `daemon.read, daemon.manage, tunnel.manage, access.manage, workspace.read, workspace.write, workspace.manage, automation.manage, hub.execute`. Admission yields `{principalId:"owner", permissions: OWNER_PERMISSIONS (all)}`; `SessionAuthorization` (`S/authorization/index.ts`) checks every inbound message type against `INBOUND_PERMISSION` and filters outbound ones (`operation-permissions.ts`). `server_info.permissions` tells the client what it holds. Examples: `hosts.list.request` daemon.read; `hosts.add/update/remove.request` tunnel.manage; `daemon.get_pairing_offer.request` access.manage; `daemon.config.reload.request` daemon.manage; `client_heartbeat` workspace.read. Roles (owner/operator/viewer) are described as UI presets only (docs/permissions.md); no UI found.
- Network gates before auth: Host header allowlist (TCP only) `isHostnameAllowed` (`S/hostnames.ts`; `hostnames === true` allows any; default allows `localhost`, `*.localhost`, any IP; patterns like `.example.com`), CORS allowlist (fixed: `paseo://app`, `http://{host}:{port}`, localhost, 127.0.0.1 plus `daemon.cors.allowedOrigins`), WebSocket upgrade check `verifyWsUpgrade` (`websocket-server.ts:940-973`: 503 "Server not ready" until accepting, 403 "Host not allowed", 403 "Origin not allowed"; allowed if no Origin header, `*`, listed, or same-origin incl. loopback aliases). Express `trust proxy` from `daemon.trustedProxies`.
### Connections
hello/admission feeds every session (agents, terminals...). Local credential couples desktop app and daemon. Hub relationship (`hub.management.daemon.*` RPCs, `S/hub/`, `docs/hub.md`) uses permissions `tunnel.manage` and `hub.execute`; it is an opt-in daemon-to-Hub link (CLI `paseo hub connect`), no app UI found in `A/` (grep `hub.management` in `packages/app/src` returned nothing).

## WebSocket session transport, keepalive, liveness
- Endpoint: daemon HTTP server upgrades `/ws` (client URL `buildDaemonWebSocketUrl` = `ws[s]://host:port/ws`, `P/daemon-endpoints.ts:228`), unix socket `ws+unix://<path>:/ws`, Windows pipe. Messages: `hello` first, then `{type:"session", message}` envelopes, `ping`/`pong` at WS level (server replies `{type:"pong"}` and claims the application-socket lease, `websocket-server.ts:2580-2587`).
- Handshake: client `hello {clientId, clientType: "mobile"|"browser"|"cli"|"mcp"|"hub", protocolVersion, appVersion?, auth?, capabilities{...CLIENT_CAPS}, routed?, producer?, sessionPermissions?}`; daemon answers with a `status` payload `server_info` (`ServerInfoStatusPayloadSchema`, `P:3659`): `serverId, hostname, version, protocolVersion, sourceId, permissions, desktopManaged, capabilities, features{...}` (features include `daemonStatusRpc`, `relayConfig`, `daemonDiagnostics`, `connectedHosts`, `hostMultiplexing`, `terminalsSurviveRestart`, `directorySync`, ... each gated in the app). The app uses `clientType: "mobile"` for all app clients (`A/runtime/host-runtime.ts` base config).
- Session survival: a session whose sockets all closed stays for `EXTERNAL_SESSION_DISCONNECT_GRACE_MS = 90_000` so a reconnect with the same `clientId` resumes it (`websocket-server.ts:2330-2345`); routed and plugin sessions end immediately. Application socket lease: `APPLICATION_SOCKET_LEASE_MS = 45_000`, check every `APPLICATION_SOCKET_LEASE_CHECK_INTERVAL_MS = 10_000` (`S/websocket/physical-socket.ts:7-8`) closes sockets that stop pinging.
- Client keepalive/reconnect (`C/daemon-client.ts:1123-1137`): `DEFAULT_CONNECT_TIMEOUT_MS = 15_000`, `DEFAULT_SESSION_RPC_TIMEOUT_MS = 60_000`, `LIVENESS_HEARTBEAT_INTERVAL_MS = 10_000`, `LIVENESS_HEARTBEAT_TIMEOUT_MS = 15_000`, `DEFAULT_LIVENESS_TIMEOUT_MS = 5000`, `LIVENESS_FAILURE_RECONNECT_THRESHOLD = 2` consecutive failed pings force a reconnect; reconnect delay `min(maxDelay, base * 2^attempt)` with `DEFAULT_RECONNECT_BASE_DELAY_MS = 1500`, `DEFAULT_RECONNECT_MAX_DELAY_MS = 30000`; reconnect disabled after an auth failure or a relay security failure. `ping` request/`pong` response (`P:2971`, session.ts emits `pong {requestId, clientSentAt, serverReceivedAt, serverSentAt}`) used by `measureLatency` (`C:2542`). `client_heartbeat {deviceType: web|mobile, focusedAgentId, focusedTerminalId, lastActivityAt, appVisible, appVisibilityChangedAt}` is sent by `A/hooks/use-client-activity.ts` (notification/attention area; listed in cross-area).
- Chunked binary transport (`P/chunked-transport.ts`, capability `binaryChunkingV1`), frame limit default 32 MiB (`ws.maxFrameBytes ?? 32*1024*1024`).
- Outbound proxy support: `initializeEnvironmentProxy` installs an undici `EnvHttpProxyAgent` from `http_proxy/HTTP_PROXY/https_proxy/HTTPS_PROXY/no_proxy` (bypass always adds `localhost,127.0.0.1,[::1],::1`; invalid values are ignored and their names logged) and `webSocketProxyAgent(url)` gives `ws` an `HttpsProxyAgent` (`S/network/index.ts`). Used by relay transport and connected-host links. Local service connections use dual-stack loopback lookup (`S/local-service-connection.ts`).

## Relay (cloud relay, daemon outbound transport)
### What the user sees / does
- Off by default (`daemon.relay.enabled: false` in the default config; runtime default in `MutableDaemonConfig` is `{enabled:true}` only when `initial.relay` absent, `daemon-config-store.ts:379`). Enabled from the app via "Enable relay" in Pair device (see Pairing), via `paseo daemon pair --relay`, config `daemon.relay.*`, env `PASEO_RELAY_*`, or CLI `--relay`/`--no-relay`.
- Hosted relay: `relay.paseo.sh:443` (TLS), `DEFAULT_RELAY_ENDPOINT` in `P/daemon-endpoints.ts:78` and `S/config.ts:39`.
### How it works
- Daemon side: `createRelayRuntime` (`S/relay-runtime.ts`) wraps `startRelayTransport` (`S/relay-transport.ts`), toggled live by `daemonConfigStore.onFieldChange("relay.enabled")` (`bootstrap.ts:1925`). Started after the WebSocket server accepts connections (`:1897`).
- Relay v2 protocol (`CURRENT_RELAY_PROTOCOL_VERSION "2"`, v1 legacy still accepted; query `v=`): daemon opens a *control* socket `wss://<relay>/ws?serverId=<id>&role=server&v=2` (one per serverId) and, for every client connection, a *data* socket `...&role=server&connectionId=<id>&v=2`. Client opens `...&role=client&v=2` (relay assigns connectionId). Control messages (JSON): `sync {connectionIds[]}`, `connected {connectionId}`, `disconnected {connectionId}`, `ping`/`pong`. Daemon keepalive: WS ping every `CONTROL_PING_INTERVAL_MS = 10_000`, stale after `CONTROL_STALE_TIMEOUT_MS = 30_000` => terminate and reconnect; first control message must arrive within `CONTROL_READY_TIMEOUT_MS = 8_000`; handshake timeout 10 s (`RELAY_WEBSOCKET_OPTIONS`), `autoSelectFamilyAttemptTimeout 5_000`; data socket open timeout 15 000 ms; reconnect delay `min(30000, 1000 * attempt)`.
- Data socket => `admitSecuredRelaySocket` (`S/websocket/secure-relay-ingress.ts`, handshake timeout `HANDSHAKE_TIMEOUT_MS = 15_000`) runs the E2EE channel then `wsServer.attachExternalSocket(secured.socket, {transport:"relay", externalSessionKey:"session:<connectionId>", securityMode})`; from there it is an ordinary session (hello/auth/permissions apply).
- Relay server (`packages/relay`, `wrangler.toml`): Cloudflare Durable Object `RelayDurableObject` (R/cloudflare-adapter.ts:133) per `relay-v{version}:{serverId}`, WebSocket hibernation, forwards frames between role/connectionId sockets, buffers client frames until the daemon data socket exists, replaces duplicate sockets with close `1008 "Replaced by new connection"`, closes `1011 "Control unresponsive"`, `1001 "Client disconnected"`, `1012 "Server disconnected"`; `/health` returns `{status:"ok"}`; upstream cutover proxy env `PASEO_RELAY_UPSTREAM`; HTTP 426 when not a WebSocket upgrade, 400 for missing role/serverId or bad `v`.
- End-to-end encryption (`R/secure-channel.ts`, `R/encrypted-channel.ts`, `docs/relay-endpoint-security.md`): relay sees only ciphertext. Two modes: `protected` = `Noise_NK_25519_ChaChaPoly_SHA256` bound to the daemon static key, prologue `"paseo-relay-e2ee/1"`, authenticated record framing with replay protection (`R/protected-records.ts`; handshake carried base64 inside `e2ee_hello`/`e2ee_ready` JSON envelopes under `protected`); `legacy` = old ephemeral-static NaCl box without replay protection. A present-but-invalid `protected` field never falls back. Close codes `1008` "protected endpoint security required", `4002` handshake failed, `4003` record failed, `1011` daemon record failure. Constants `HANDSHAKE_RETRY_MS = 1000`, `MAX_PENDING_SENDS = 200`.
- Policy: config `daemon.relay.requireProtectedSecurity` (hot-reloadable; default false) makes the daemon refuse legacy clients; pairing offers carry `minimumSecurityMode:"protected"` when set so new clients pin it from the first handshake; the app pins a daemon identity to protected once it has negotiated it (`HostRuntimeController` `onRelayProtectedSecurityNegotiated` => `pinRelayProtectedSecurityInProfiles`, `A/types/host-connection.ts:~270`; the pin is shared across every relay route to the same daemon key and never cleared by failures).
### States, errors
Relay failure in the app shows as connection status `offline`/`error` plus `lastError`; E2EE failure disables reconnect for that client (`securityFailure` in `C/daemon-client.ts:1636`).
### Connections
Pairing (offers), hosts (relay `HostConnection`), settings (relay toggle), diagnostics (relay config reported in `daemon.get_status.response.relay`).

## Pairing: connection offers, links, QR, scan, confirmation
### What the user sees / does

## Connected hosts (daemon-to-daemon links) and routed hosts in the app
### What the user sees / does
- CLI: `paseo host ls|add|update|remove|...` against a selected daemon (`cli/src/commands/host/index.ts`: `add --label --meta k=v`, `update --label --connection --replace-identity --meta --remove-meta`, enable/disable/remove actions by `<registration-id>`). ### How it works
- Storage: `$PASEO_HOME/hosts.json` (mode 0600, atomic temp+rename, array of `HostSummary + {connection}` rows; `connection` secret never returned by reads) owned by `ConnectedHosts` (`S/connected-hosts/index.ts`). Max 128 registrations (`resource_limit`), max 128 routed sessions, route handshake timeout 15 000 ms, connect timeout 10 000 ms; retries delegated to the shared client reconnect (`nextRetryAt` surfaced).
- Protocol (`P/hosts.ts`): `hosts.list.request {observe?}` => `hosts.list.response {directory{self{serverId,label}, hosts[]}, subscriptionId?}`; push `hosts.changed {subscriptionId, directory}`; `hosts.add.request {input{connection(<=16384 chars), label?, metadata?, sourceKey?}}`; `hosts.update.request {registrationId, patch{label|null, metadata, enabled, connection, replaceIdentity}}`; `hosts.remove.request`; routing: `hosts.route.open.request {serverId, scopeId}` => `.response {routeId}`, `hosts.route.frame.request/.frame {data, binary:false}` (base64 text frames up to 100 MiB), `hosts.route.close.request`, `hosts.route.closed {code,message}`, plus `hosts.link.open.request {channelId}` for the B side. `HostSummary {registrationId "hst_<uuid>", serverId|null (learned), label, source{id,key}, metadata, enabled, status: connecting|online|offline|error|disabled, targetDescription, lastOnlineAt, nextRetryAt, error{code,message}}`. Error codes: `host_unknown, host_offline, duplicate_host, source_conflict, permission_denied, invalid_connection, resource_limit, invalid_message, authentication_failed`.
- Authority: list `daemon.read`; add/update/remove `tunnel.manage`; replacing connection/metadata/identity needs the producer (same `source.id`) or `access.manage`. Identity (serverId) is pinned when first learned; changed destination requires `replaceIdentity`. Self and duplicate registrations are inspectable. Capability gates: both daemons advertise `features.connectedHosts`; physical sharing needs `hostMultiplexing`.
- Client: `DaemonClient.observeHosts()` / host actions (`C/daemon-client.ts:1832-1872`, `C/hosts/index.ts` `PaseoHostActions {list, observe, add, update, remove, client(serverId)}`, `createHostChannelTransport`). Connection targets use the same grammar as `parseHostTarget` (including `ssh://`), shared Node connector `createHostClient` (`@getpaseo/client/node`) with `HostTransportBudget`.
- App discovery: `HostRuntimeStore.syncHostDiscovery(serverId)` (`A/runtime/host-runtime.ts:2457`): for each online host with `features.connectedHosts` (and not itself reached through a routed connection) it opens `client.observeHosts()`; every discovered `target.serverId != origin` is upserted into the registry with connection `{id:"via:<origin>", type:"routed", originServerId}` and gets a fleet directory demand (`acquireDirectoryDemand`). Routed `DaemonClient` is created with a transport over the origin client (`createDefaultDeps().createClient`, `routed` branch; throws "Origin host X is unavailable" if the origin is gone). Routed sessions are admitted under the physical link principal; caller grants are intersected (`hello.routed`, `hello.producer {serverId, sourceId}`; `server_info.sourceId`).
### Connections
Agents area (remote create/prompt/watch via MCP), host registry (routed connections), permissions.

A manual stop of a non-owned daemon requires confirming `{pid, startedAt}` ("Daemon changed since confirmation..." otherwise). `stopCapturedDaemon` falls back to a terminal-closing stop when the daemon predates keep-terminals (`TERMINALS_KEEP_UNSUPPORTED`).

Remote-host restart in app (`restartDaemonFromSettings`, `A/screens/settings/daemon-lifecycle.ts`): `restartServer(reason, {killTerminals})`, then polls `getDaemonStatus` every 250 ms until a different worker `pid` reports ready (deadline 600 000 ms), and if `killTerminals` verifies `terminalCleanupUnconfirmed` is empty (else error listing pid/role/reason/detail). - Local transport: the app talks to the desktop daemon over unix socket / Windows pipe through the main process (`open_local_daemon_transport` etc., `D/daemon/local-transport.ts`, events `TransportEventPayload {sessionId, kind: open|message|close|error, text, binaryBase64, code, reason, error}`), wrapped by `A/desktop/daemon/desktop-daemon-transport.ts` as a `DaemonTransportFactory`.

### What the user sees / does

### How it works
- App: `DesktopAppUpdater` store (`A/desktop/updates/desktop-app-updater.ts`) states `idle|checking|pending|up-to-date|available|installing|installed|error`, `PENDING_RECHECK_MS = 10_000` re-check while an update is still downloading; hook `useDesktopAppUpdater`. IPC `check_app_update {releaseChannel?, intent: "automatic"|"manual"}` => `D/features/auto-updater.ts` + `app-update-service.ts` over `electron-updater` (provider GitHub `getpaseo/paseo`, channel `latest` or `beta`, `allowPrerelease` on beta, `autoDownload=true`, `autoInstallOnAppQuit=false`, `allowDowngrade=false`) returning `{hasUpdate, readyToInstall, currentVersion, latestVersion, body, date, errorMessage}`; `install_app_update` stops the daemon (`app_update`, terminals kept on POSIX) then `quitAndInstall`. Missing channel file (`ERR_UPDATER_CHANNEL_FILE_NOT_FOUND`) is treated as no update.
- Staged rollout (stable only, automatic intent only; `D/features/app-update-rollout.ts`): manifest field `rolloutHours` (number|string) and `releaseDate`; admitted when `bucket*100 < min(100, ageHours/rolloutHours*100)`, bucket = uint32 from a persisted staging user id UUID (`getStagingUserId`); manual checks and beta always admitted; `rolloutHours` 0/absent/invalid date admit.
- Daemon self-update RPC (non-desktop-managed daemons): `daemon.update.request {requestId}` => progress pushes `daemon.update.progress {requestId, phase: starting|downloading|installing|complete}` => `daemon.update.response {requestId, success, error, previousVersion, newVersion}` (`P:6703-6720`); handler `S/session/daemon/daemon-self-update-session-controller.ts` -> `daemon-self-updater.ts`: refuses desktop-managed ("This daemon is managed by Paseo Desktop. Update Paseo Desktop on the host."), only one at a time (`rpc_error` code `already_updating`), validates npm-global install origin (`install-origin.ts`: not linked, version matches, server package under the npm global prefix), runs `npm install -g` latest (`npm-global-cli.ts`), then emits lifecycle intent restart reason `daemon_update` keepTerminals true. App flow `updateDaemonFromSettings` waits for a different worker pid and asserts worker version == installed `newVersion` (same 600 s deadline). Client `DaemonClient.updateDaemon` (`C:4219`). Permission `daemon.manage`.
- Desktop daemon version drift: a newer app auto-restarts the owned daemon on next start (see above); `isVersionMismatch(appVersion, daemonVersion)` shows warnings.
### Connections
Settings (releaseChannel in desktop-settings.json), sidebar callouts, daemon lifecycle, changelog link ("What's new").
