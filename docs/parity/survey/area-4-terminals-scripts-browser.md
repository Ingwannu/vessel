## 1. Terminal sessions on the daemon (PTY, headless xterm state, workers)

### 1.1 What a terminal is
- A terminal = one PTY (node-pty) + one headless xterm (`@xterm/headless`, scrollback 10000 lines, `terminal.ts:~795` `createHeadlessTerminal({rows, cols, scrollback: 10000})`) that mirrors screen state so the daemon can snapshot, replay, capture and serialize it.
- Created by `createTerminal()` (`server/src/terminal/terminal.ts:750`). Defaults: `rows=24, cols=80, name="Terminal"`; shell = `resolveDefaultTerminalShell` (`$SHELL` or `/bin/sh`; Windows `%ComSpec%` or cmd.exe); a `command` + `args` runs that program directly instead of the shell (`resolveTerminalSpawnCommand`, handles Windows `.cmd/.bat` via a pre-escaped cmd.exe line, `terminal.ts:277-415`). `assertTerminalCommandCanStart` fails early with `TerminalCommandNotFoundError` (command not on PATH / cwd missing).
- Env (`buildTerminalEnvironment`, `terminal.ts:449`): starts from the caller's `baseEnv` (worker gets the daemon env) + per-create `env`; forces `TERM=xterm-256color`, `TERM_PROGRAM=kitty`; prepends the Paseo CLI bin dir to PATH; sets `PASEO_HOOK_CLI`; always sets `PASEO_WORKSPACE_ID`, and (via the manager) `PASEO_TERMINAL_ID`, `PASEO_ACTIVITY_TOKEN` (32 random bytes base64url, per terminal), `PASEO_TERMINAL_ACTIVITY_URL` (the loopback `/api/terminal-activity` URL). For zsh it swaps `ZDOTDIR` to a runtime dir that sources `terminal/shell-integration/zsh/paseo-integration.zsh` (emits OSC 633 `A/B/C/D;<status>` and OSC 2 title with `~` abbreviation) and keeps the user's original in `PASEO_ZSH_ZDOTDIR`.
- Terminal protocol answers done by the daemon-side headless xterm (so the browser/native renderer never answers): DA1 (`CSI c` -> `ESC[?62;4;22c`), DSR 5 and 6 (cursor position), DECXCPR, OSC color queries (`TERMINAL_OSC_COLOR_QUERY_RESPONSES`). Input-mode tracking (`TerminalInputModeTracker`, `protocol/src/terminal-input-mode.ts`): kitty keyboard flags, win32-input-mode 9001, application cursor keys (1), bracketed paste (2004); the tracker state is replayed to a new subscriber as `replayPreamble`.
- Title: auto mode follows OSC 0/2 (`TERMINAL_TITLE_DEBOUNCE_MS = 150`); a preset `title` or a rename switches to manual mode. For `command` terminals the initial title is `humanizeProcessTitle(command args)` (strips interpreters and path, maps package-manager scripts).
- Command lifecycle: OSC 633;D parsed by `parseCommandFinishedOsc` -> `onCommandFinished({exitCode|null})` (used by plain scripts, see section 6).
- Exit: `TerminalExitInfo {exitCode, signal, lastOutputLines}`; last 12 lines (`TERMINAL_EXIT_OUTPUT_LINE_LIMIT`) taken from xterm or from the last 16000 chars of raw output (`TERMINAL_EXIT_OUTPUT_CHAR_LIMIT`).
- Kill: `killAndWait` graceful 2000 ms then force 1000 ms (`terminal.ts:1346`). Input is coalesced per tick (`pendingInput`, `setImmediate`).
- Resize: `send({type:"resize"})` resizes both headless xterm and PTY.
- Capture (`terminal/terminal-capture.ts`): `captureTerminalLines(buffer, {start,end,stripAnsi})`, negative indices count from the end, indices clamped; default `stripAnsi=true`; returns `{lines, totalLines}`.

### 1.2 Terminal manager and the worker process
- `TerminalManager` interface (`server/src/terminal/terminal-manager.ts:57`): `getTerminals(cwd,{workspaceId})`, `createTerminal`, `getTerminal`, `replayTerminal`, `setTerminalTitle`, `setTerminalActivity`, `clearTerminalAttention`, `killTerminal`, `killTerminalAndWait`, `captureTerminal`, `listDirectories`, `killAll`, `subscribeTerminalsChanged`, `subscribeTerminalActivity`, `subscribeTerminalWorkspaceContributionChanged`, `registerCwdEnv`, `validateTerminalActivityToken`. `createTerminalManager` (:127) is the in-process implementation, indexed by cwd and id.
- Production uses the worker architecture: `startWorkerTerminalManager` (`worker-terminal-manager.ts`, called in `server/bootstrap.ts:723`). PTYs live in a **detached terminal worker process** (`terminal-worker-process.ts`) re-parented to init, so a daemon restart/crash does not kill terminals. Daemon <-> worker: owner-only unix socket (`terminal-worker-socket-path.ts`, byte budget 103), length-framed JSON (`terminal-worker-frames.ts`, `MAX_FRAME_BYTES = 256 MiB`), auth by a secret from the worker record. `TERMINAL_WORKER_PROTOCOL_VERSION = 5`.
- Worker record: `$PASEO_HOME/...` `<pid>.json` (`terminal-worker-record.ts`, zod schema: recordId, pid, bootId, createdAt, identity{startedAt, commandLine}, protocolVersion, paseoVersion, socketPath, secret, runtime, terminals[{id,pid,startedAt}], optional `closing`), written by the worker whenever a terminal starts/exits; cleanup state in `closing-<recordId>.json`. Process identity = birth time from `ps` (`terminal-worker-processes.ts`, `PS_TIMEOUT_MS = 15000`), never pid alone.
- Pool (`terminal-worker-pool.ts`): up to `MAX_TERMINAL_WORKERS = 2`: one current worker (takes all new terminals) + one draining worker (older protocol; serves its existing terminals and is released when its last one exits, `DRAINED_WORKER_EXIT_TIMEOUT_MS = 10000`). A worker from a **newer** Paseo is never driven: terminal RPCs fail with `TerminalWorkerIncompatibleError` (code `terminal_worker_incompatible`, sent as `rpc_error`; message tells user to update Paseo or run `paseo daemon stop`). `NoTerminalWorkerAvailableError` when none may start.
- Timeouts: worker request `REQUEST_TIMEOUT_MS = 10000`; launcher `LAUNCH_TIMEOUT_MS = 20000`, `READY_TIMEOUT_MS = 15000`, `HELLO_TIMEOUT_MS = 5000`, `FIRST_CONTROLLER_TIMEOUT_MS = 30000`, orphan check every `ORPHAN_CHECK_INTERVAL_MS = 10000` (record deleted -> worker exits); reaper (`terminal-worker-reaper.ts`) graceful 5000 / confirm 3000 / poll 100 ms; client connect `DEFAULT_CONNECT_TIMEOUT_MS = 5000`. Worker stalled controller: if `writableLength > 4 MiB` the socket is destroyed and observers reconnect.
- Daemon shutdown (`bootstrap.ts:~2000`): `keepTerminals` true -> `terminalManager.detach()` (terminals keep running for the next daemon); else `closeTerminals()` and retry from the kept record. Archive workspace -> `killTerminalsForWorkspace`.
- Storage: only the worker records and sockets under `$PASEO_HOME` (and `runtime/terminal-worker` copies of worker code, `terminal-worker-runtime.ts`, marker `paseo-terminal-worker-runtime.json`). No sqlite. Terminal content itself is never persisted.

### 1.3 Wire protocol for terminals (WS)
Requests (client -> daemon), `protocol/src/messages.ts:3020-3160`:
- `list_terminals_request {cwd?, workspaceId?, requestId}` -> `list_terminals_response {cwd?, terminals[{id,name,cwd,workspaceId?,title?,activity?}], requestId}` (handler `terminal-session-controller.ts handleListTerminalsRequest`; with workspaceId filters all sessions by workspace; with cwd filters by owning workspace root, longest-prefix wins).
- `subscribe_terminals_request {requestId?, cwd, workspaceId?}` -> a `terminals_changed {subscriptionId?, requestId?, workspaceId?, cwd, terminals[]}` snapshot immediately and on every change (owned subscription kind `terminal-directories`, key `terminalSubscriptionKey(cwd, workspaceId)`). `unsubscribe_terminals_request`.
- `create_terminal_request {cwd, workspaceId?, name?, agentId?, command?, args?, size?{rows,cols}, requestId}` -> `create_terminal_response {terminal|null, error|null, requestId}`. Errors: `agentId` present -> "Agent-backed terminals are no longer supported for agent X"; no workspace -> `"workspaceId is required"` (legacy: workspace resolved from cwd by exact match or owner root); `Workspace X is not active or does not exist`; spawn failure message. `size` is optional and honored forever (the app no longer sends it; the pane-focus resize claim sizes the PTY).
- `terminal.rename.request {terminalId,title,requestId}` -> `terminal.rename.response {requestId,success,error}`; title trimmed, empty -> "Title is required", >200 chars -> "Title is too long", unknown -> "Terminal not found".
- `subscribe_terminal_request {terminalId, requestId, restore?{mode:"live"|"visible-snapshot"|"full-snapshot", scrollbackLines?, size?}}` -> `subscribe_terminal_response {terminalId, slot(0..255), subscriptionId?, error:null, requestId}` or `{terminalId,error,requestId}`. Errors: "Terminal manager not available", "Terminal not found", "No terminal stream slots available" (`MAX_TERMINAL_STREAM_SLOTS = 256`). `unsubscribe_terminal_request {terminalId}`. Client default restore when none given is `{mode:"full-snapshot"}` (`client daemon-client.ts observeTerminal`, :6489).
- `terminal_input {terminalId, message}` where message is `{type:"input",data}` | `{type:"resize",rows,cols,intent?:"claim"|"update"}` | `{type:"mouse",row,col,button,action:"down"|"up"|"move"}` (fire and forget; `client.sendTerminalInput`).
- `kill_terminal_request {terminalId,requestId}` -> `kill_terminal_response {terminalId,success,requestId}`.
- `capture_terminal_request {terminalId,start?,end?,stripAnsi(default true),requestId}` -> `capture_terminal_response {terminalId,lines,totalLines,requestId}` (unknown terminal/error -> empty lines, totalLines 0).
- Pushed: `terminals_changed`, `terminal_stream_exit {subscriptionId?,terminalId,error?}` (no error = PTY exited; with error = observation failure while the process may still run), `terminal_attention_required {subscriptionId?,serverId?,terminalId,cwd,workspaceId?,reason:"finished"|"needs_input",title,body,shouldNotify}`.
- Permissions (`server/authorization/operation-permissions.ts`): read = list/subscribe/capture (`workspace.read`); write = create/kill/rename/input (`workspace.write`).
- Capability flags in server info `features` (`websocket-server.ts:~2075`): `terminal-restore-modes`, `terminal-input-mode-replay`, `terminal-size-ownership`, `terminal-grapheme-widths`; client caps `terminal_chunked_replay`, `terminal_reflowable_snapshot` (`protocol/src/client-capabilities.ts`).

Binary terminal stream (WS binary frames, `protocol/src/binary-frames/terminal.ts`): frame = `[opcode u8][slot u8][payload]`. Opcodes `Output 0x01, Input 0x02, Resize 0x03 (JSON {rows,cols,intent?}), Snapshot 0x04 (JSON TerminalState), Restore 0x05 (one blob replay, legacy), ReplayBegin 0x06 (JSON {rows,cols,retainedHistoryLines}), ReplayData 0x07, ReplayEnd 0x08`. `TerminalState` = `{rows, cols, grid[][cell], scrollback[][cell], cursor{row,col,hidden?,style?,blink?}, title?, gridWrapped?, scrollbackWrapped?}`, cell = `{char, fg,bg,fgMode,bgMode,bold,italic,underline,dim,inverse,strikethrough}`.

### 1.4 Terminal session controller (per WS session) - how output reaches a client
`server/src/terminal/terminal-session-controller.ts:136`.
1. `handleSubscribeTerminalRequest` opens an owned subscription `terminal-output`, allocates a slot (round-robin over 256, `allocateSlot`), emits `subscribe_terminal_response`, then `trySendSnapshot`.
2. `bindActiveStream`: subscribes to the terminal; live output goes through a `TerminalOutputCoalescer` (`terminal-output-coalescer.ts`: leading-edge flush if >=`DEFAULT_FLUSH_DELAY_MS = 5` ms since last flush, else trailing timer) and out as `Output` frames.
3. Restore: `resolveTerminalRestoreSnapshotOptions` (`terminal-restore.ts`): `live` = no snapshot; `visible-snapshot` = `scrollbackLines ?? 200` (`DEFAULT_VISIBLE_RESTORE_SCROLLBACK_LINES`), capped to 500 (`MAX_VISIBLE_RESTORE_SCROLLBACK_LINES`) for non-chunked clients; `full-snapshot` = chunked clients get the requested scrollback, legacy clients get the whole thing. Chunked clients (`terminal_chunked_replay` cap) receive `ReplayBegin/Data/End` (data chunks of `TERMINAL_REPLAY_CHUNK_BYTES = 64 KiB`, `terminal-replay.ts`); legacy clients get one `Restore` frame. The replay carries a `revision`; buffered live output with `revision <= replay.revision` is dropped, the rest is replayed after the `replayPreamble` (input-mode escapes).
4. Back-pressure catch-up: `MAX_TERMINAL_OUTPUT_FRAME_BYTES = 256 KiB` produced since last snapshot AND (`bufferedAmount > MAX_CLIENT_BUFFERED_BYTES = 4 MiB` or transport has no signal, e.g. relay) -> drop the batch and send a fresh `visible-snapshot` (scrollback capped at 500). While a snapshot is pending, live output is buffered; if buffer exceeds 4 MiB the stream is killed with `terminal_stream_exit` error "Terminal replay live tail exceeded the buffer; attach again".
5. Input: `terminal_input` JSON or binary `Input`/`Resize` frames on the slot (source must match the owner of the slot). Resize goes through `applyTerminalSize` (`terminal-size-ownership.ts`): **intent `claim`** takes ownership (WeakRef to the source) and resizes; **`update`** is ignored unless the sender is the current owner; missing intent = `claim` (legacy). Prevents two clients (phone + desktop) fighting over the PTY size.
6. Exit/kill: `detachStream` -> `completeStream` flushes buffered output, emits `terminal_stream_exit`, releases. Kill from `close_items` batch uses `killTerminalForClose`.
7. Directory subscriptions refresh via `handleTerminalsChanged` for every subscription whose cwd is within the event cwd; coalesced (`refresh`/`pending`).

### 1.5 Terminal activity, attention, notifications
- State per terminal: `TerminalActivity {state:"idle"|"working"|"attention", attentionReason:"finished"|"needs_input"|null, changedAt}` (`protocol/src/terminal-activity.ts`). Unknown state from newer daemon degrades to "idle". `TerminalActivityTracker` (`terminal/activity/terminal-activity-tracker.ts`): unknown != idle (a plain shell has no activity); `set("idle")` after "working" -> idle + `finished`; "attention" -> idle + `needs_input`; Ctrl-C (`\x03`) or ESC input while working clears to null (`interrupt`); `clearAttention()` when the user looks.
- Input source: hooks. `POST /api/terminal-activity` (`server/bootstrap.ts:314 createTerminalActivityRouteHandler`) accepts `{terminalId, token, state:"running"|"idle"|"needs-input"}` -> mapped to `working|idle|attention`; loopback only (403 otherwise), token must match the terminal's `PASEO_ACTIVITY_TOKEN`. Callers: `paseo hooks ...` CLI (`cli/src/commands/hooks.ts`, "Record agent hook activity") invoked by installed agent hooks for Claude, Codex and OpenCode (`server/terminal/agent-hooks/{claude,codex,opencode}`).
- Setting `enableTerminalAgentHooks` (daemon config; `applyTerminalAgentHookSetting`): on = install hooks into the user's real agent config files; off = remove marker-matched hooks. Default off. UI: host page card `EnableTerminalAgentHooksCard` (`app/screens/settings/host-page.tsx:943`, testID `host-page-terminal-agent-hooks-switch`).
- Attention fan-out: `websocket-server.ts:841` subscribes to terminal activity; `resolveTerminalAttentionReason` (:201) = `finished` / `needs_input` / state "attention" or working->idle. `broadcastTerminalAttention` (:2955) picks clients that subscribe to that terminal directory (or modern sources that want the event), computes `computeNotificationPlan` with client presence (focused terminal, app visibility), may send a push (title "Terminal needs input" / "Terminal finished", body = terminal name, data serverId/terminalId/cwd/workspaceId) and sets `shouldNotify` for exactly one in-app recipient.
- App: `contexts/session-context.tsx:658` -> `sendOsNotification` if `shouldNotify`, data routes a tap to the terminal tab. Client heartbeat carries `focusedTerminalId`; `session.ts:5064` calls `clearTerminalAttention` when the app is visible and that terminal is focused.
- Workspace roll-up: `terminal-manager` emits workspace contribution changes (`subscribeTerminalWorkspaceContributionChanged`) -> `session.ts:6266 emitWorkspaceUpdateForTerminalContribution` so workspace status (sidebar bucket) reflects terminal activity; bucket derived by `deriveTerminalActivityStatusBucket`: needs_input -> "needs_input", finished -> "attention", working -> "running".

### 2.3 Web/desktop emulator (xterm.js) - `app/terminal/runtime/terminal-emulator-runtime.ts`, `components/terminal-emulator.tsx`

### 6.2 Runtime: start / stop / restart (`server/worktree-bootstrap.ts:518 spawnWorkspaceScript`)
Entry points: WS `workspace.script.list|start|stop.request` (`protocol/src/messages.ts:3069-3094`) and legacy `start_workspace_script_request`; MCP tools `list_workspace_scripts`, `start_workspace_script`, `stop_workspace_script` (`paseo-tools.ts:2368-2440`); CLI `paseo script ls|start <name>|stop <name>` (`cli/src/commands/script/*`, `--cwd`); desktop/app UI (6.5). Permissions `workspace.write` for start/stop (`operation-permissions.ts:191,221`). Daemon service object: `createWorkspaceScriptsService` (`server/session/workspace-scripts/workspace-scripts-service.ts:54`: `buildSnapshot, emitStatusUpdate, list, launch, stop, start`). Not available -> error "Workspace scripts are not available on this daemon" (needs terminalManager + serviceProxy + runtimeStore). Start first runs `assertAutomationAllowed(workspaceId)`.
- Start flow: read config; unknown name -> `Script 'X' is not configured in paseo.json`; already running -> `Script 'X' is already running`; for a **service**: plan ports for all services in the workspace, assert no env-name collisions, register the proxy route, build env; acquire terminal (services always get a fresh terminal named/titled by script name with the service env; plain scripts **reuse** the previous terminal if it is still alive); record runtime `{type, lifecycle:"running", terminalId, exitCode:null}`; subscribe to terminal exit (and for plain scripts to `onCommandFinished`); for a new terminal wait for first output or 1500 ms; type `config.command + "\r"` into the terminal. Failure rolls back route and runtime entry and rethrows.
- Stop: only if runtime says running and the terminal still exists ("Script 'X' is not running" / "Terminal for script 'X' is no longer available"); `killTerminalAndWait(terminalId)`; the launcher's exit listener removes the route and marks the entry stopped.
- Exit handling (`stopRuntimeIfCurrent`): on terminal exit -> remove service route, runtime `lifecycle:"stopped"`, `exitCode` from the terminal; plain scripts also stop on OSC 633;D (command finished) with that exit code but keep the terminal open for reuse; service routes are removed on exit only.
- Restart: not a daemon RPC. App kills the terminal, waits until the daemon projects `lifecycle != "running"`, then starts again (`use-workspace-script-actions.ts:~125`, `pendingRestartRef`).
- Cleanup: archive workspace -> `scriptRuntimeStore.removeForWorkspace` + `releaseWorkspaceServicePortPlan` (`bootstrap.ts:1071`, `session.ts:6098`); worktree teardown `teardownWorktreeScripts(hostnames)` removes routes; runtime store is in memory only (daemon restart forgets running state; terminals survive in the worker but are no longer associated with the script).
- Runtime store (`workspace-script-runtime-store.ts`): `ScriptRuntimeEntry {workspaceId, scriptName, type:"script"|"service", lifecycle:"running"|"stopped", terminalId, exitCode}`; keyed by workspaceId + scriptName.

### 6.3 Service env and ports
- Env injected into a service terminal (`workspace-service-env.ts:25`): `HOST` = `127.0.0.1` if the daemon listens on loopback (or unset) else `0.0.0.0` (`resolveServiceBindHost`), `PASEO_PORT=<own port>`, `PASEO_URL=<own proxy url>` (public url if configured else `http://<host>.localhost:<daemonPort>`), and for every service in the workspace (including itself) `PASEO_SERVICE_<NAME>_PORT` and `PASEO_SERVICE_<NAME>_URL` where `<NAME>` = script name upper-cased with non `[A-Z0-9]` runs replaced by `_` and trimmed; two services mapping to the same NAME throw "Service env name collision for X: a, b".
- Port plan (`workspace-service-port-registry.ts`): per-workspace map scriptName -> port, created once (`ensureWorkspaceServicePortPlan`) so peers can reference each other before they run; explicit `port` values are reserved first (duplicates throw "Service 'X' has a duplicate port N"); dynamic ports are owned process-wide (`dynamicPortOwners`) so two workspaces never share one; up to `MAX_DYNAMIC_PORT_ALLOCATION_ATTEMPTS = 10` tries ("Could not allocate a unique port for service 'X' after 10 attempts"); a stopped service is re-allocated on next start (`refreshWorkspaceServicePort`); plan released on archive (`releaseWorkspaceServicePortPlan`); concurrent plan updates serialized with a pending-promise and a release token.
- Allocation (`workspace-service-port-allocator.ts:25`): `portScript` -> executed without shell with args `[scriptName, workspaceId, branchName, cwd]` and env `PASEO_SCRIPTNAME, PASEO_WORKSPACE_ID, PASEO_BRANCH_NAME, PASEO_WORKTREE_PATH`, `PORT_SCRIPT_TIMEOUT_MS = 10000`, `PORT_SCRIPT_MAX_OUTPUT_BYTES = 1024`, stdout must be exactly one integer 1..65535 and not reserved; else `range` -> random start, linear probe, availability checked by binding `127.0.0.1` ("No available service port in configured range a-b"); else `findFreePort()` (bind port 0 on 127.0.0.1).
- **Port discovery** (detecting ports a user process opened, e.g. lsof/netstat scanning): not found (searched `lsof|netstat|ss -ltn|discoverPorts|detectPort|listening port` in `server/src` and `app/src`). Paseo only knows ports it allocated/declared for services.

### 6.4 Service proxy / "script proxy" / service routes (`server/service-proxy.ts`, `script-proxy.ts` re-exports it)
- Routes: `ServiceProxyRouteRegistry` (also exported as `ScriptRouteStore`): hostname -> `{hostname, port, workspaceId, projectSlug, scriptName, publicHostname?, publicBaseUrl?}` with alias map (local + public hostname), workspace index, collision error `ServiceProxyRouteCollisionError` (a different workspace/script owning the same hostname).
- Hostnames: label = `<script>--<branch>--<project>` (branch omitted when null/`main`/`master`), each part lower-cased, NFKD-stripped, non `[a-z0-9]` -> `-`, `untitled` when empty; DNS label capped at 63 chars with `--<8 hex sha256>` suffix (`capDnsLabel`). Local hostname `<label>.localhost`; public hostname `<label>.<publicBaseUrl host>`. Project slug from `deriveProjectServiceSlug`/`deriveProjectSlug`.
- URLs (`projectServiceProxyUrls`): `localProxyUrl = http://<label>.localhost:<daemonTcpPort>` (null if daemon not on TCP), `publicProxyUrl = <base protocol>//<label>.<base host>[:port]` when `daemon.serviceProxy.publicBaseUrl` set, `proxyUrl = public ?? local`.
- HTTP path: express middleware mounted **before** host allowlist/auth (`bootstrap.ts:777`): `classifyHost(Host)` -> `registered-service` (reverse-proxy to `localhost:<port>` via `requestLocalService`, tries 127.0.0.1 and ::1 with autoSelectFamily; hop-by-hop headers stripped; adds `x-forwarded-for` (client address), `x-forwarded-host` (verbatim Host incl. port), `x-forwarded-proto`, `x-forwarded-port` derived from Host port 1..65535; upstream error -> 502 "502 Bad Gateway"), `known-service-miss` (`*.localhost` host whose first label contains `--`, or any host under a configured public base host) -> 404 "404 Not Found" and never reaches daemon APIs, `daemon` -> `next()`. WebSocket upgrade: `httpServer.on("upgrade", serviceProxy.upgradeHandler({passthroughUnknown:true}))` (`bootstrap.ts:934`) tunnels raw TCP to the service for registered hosts; unknown hosts pass through to the daemon WS server (in standalone mode they are destroyed). Documented limitation: x-forwarded-* headers are client-influenced (no trusted-proxy check).
- Standalone listener: `daemon.serviceProxy.listen` (config / env `PASEO_SERVICE_PROXY_LISTEN`; parse `tcp host:port`, unix socket or pipe via `parseListenString`) starts a service-only express server (`startStandalone`, trust proxy true, upgrade `passthroughUnknown:false`, 404 for the rest); stop closes all connections and unlinks the socket. Public base: `daemon.serviceProxy.publicBaseUrl` / env `PASEO_SERVICE_PROXY_PUBLIC_BASE_URL` (validated URL, trailing slash stripped; error `Invalid PASEO_SERVICE_PROXY_PUBLIC_BASE_URL`). Legacy `daemon.serviceProxy.enabled=false` / `PASEO_SERVICE_PROXY_ENABLED` only suppresses these optional layers; localhost proxying is always on (`config.ts:365-388`).
- Branch rename: `createBranchChangeRouteHandler` (`script-route-branch-handler.ts`) calls `replaceWorkspaceBranchRoutes` (re-hostnames all routes of the workspace, atomic with collision checks) when the workspace branch changes, then invalidates health snapshot so clients get a new `script_status_update`.

### 6.5 Health monitor and status projection
- `ScriptHealthMonitor` (`script-health-monitor.ts:20`): polls every `pollIntervalMs = 3000` ms (single in-flight poll) each registered route by opening a TCP connection to `localhost:<port>` with `probeTimeoutMs = 500`; per-route state `pending|healthy|unhealthy`; probing starts only `graceMs = 5000` after registration; one success -> healthy and failure counter 0; `failuresBeforeStopped = 2` consecutive failures -> unhealthy (never goes back to pending). Removed routes are pruned. On a change it builds the workspace script list and calls `onChange` only if the JSON snapshot differs from the last emitted. `invalidateWorkspace(workspaceId)` forces re-emit (used on branch change). Wire health: `pending` -> `null`, others as is.
- Projection (`script-status-projection.ts:214 buildWorkspaceScriptPayloads`): for every configured script (service or plain) merges config + runtime entry + route state; runtime-only "orphan" entries appear only while running; sorted by name (numeric, case-insensitive). `WorkspaceScriptPayload {scriptName, type:"script"|"service", hostname, port|null, localProxyUrl?, publicProxyUrl?, proxyUrl, lifecycle:"running"|"stopped", health:"healthy"|"unhealthy"|null, exitCode|null, terminalId|null}` (`protocol/src/messages.ts:4072`). ### 6.7 Managed processes (helper process ledger) - `server/managed-processes/managed-processes.ts`
Not a user-facing feature: a file-backed ledger so a restarted daemon can reap helper processes the previous daemon left behind. `createManagedProcessRegistry({paseoHome, processTable, terminateProcess, logger})` (:119): records live in `$PASEO_HOME/runtime/managed-processes/<uuid>.json` (zod `ManagedProcessRecordSchema`: id, owner{provider,kind}, pid, command, args, metadata, identity{commandLine,startedAt}, createdAt; id regex `^[a-zA-Z0-9_-]+$`; atomic write). `record()` snapshots process identity (`ps -ww -p <pid> -o lstart= -o command=`, `lstart` is a 24-char field; Windows `Get-CimInstance Win32_Process` via PowerShell by absolute path). `reapStale()` at boot (`bootstrap.ts:541`, async, logs counts): not-found -> drop record; inspection error -> keep for next run; identity mismatch (pid reuse: lstart differs or command line lacks contiguous `<command> <args>`) -> drop without killing; match -> `terminateWithTreeKill` with graceful `MANAGED_PROCESS_GRACEFUL_SHUTDOWN_TIMEOUT_MS = 5000`, force `...FORCE... = 1000`, exit poll 50 ms. Corrupt records are skipped. Used by providers (OpenCode server manager `providers/opencode/server-manager.ts:559`, `opencode/v2/runtime.ts:283`) - not by scripts or terminals (terminals use the worker records of section 1.2). Connection: provider runtime (agents area).

### 7.3 Agent browser tools - daemon side (`server/browser-tools/*`)
- Feature gate: daemon config `browserTools.enabled` (default false; persisted under `daemon.browserTools.enabled`, `persisted-config.ts:263`, `daemon-config-store.ts:187,215`, policy `DaemonConfigBrowserToolsPolicy.isEnabled()`); tools are registered only when enabled and a broker exists (`paseo-tools.ts:1358 registerBrowserTools`). - Broker (`BrowserToolsBroker`, `broker.ts:48`): hosts register with `{id, hostKind, supportedCommands[], sendBrowserAutomationRequest}`; `execute({command, agentId?, cwd?, workspaceId?, requestId?, timeoutMs?})` validates against `BrowserAutomationExecuteRequestSchema`, routes `new_tab` and tab-less commands to the **most recently registered** host; `list_tabs` fans out to all hosts (merges tabs; any failing host fails the call); tab-scoped commands route to the host that owns the `browserId` (affinity learned from successful responses/list_tabs; forgotten on close_tab); if the owner disconnected the tab is "stranded" (error `browser_no_host` "The app hosting browser tab X disconnected.") and returns to its owner on reconnect; with one host and unknown tab it uses that host; with several hosts and unknown tab -> `browser_tab_not_found` "...Call browser_list_tabs...". Unsupported command for the host -> `browser_unsupported`. Default timeout `DEFAULT_BROWSER_TOOLS_TIMEOUT_MS = 15000` -> `browser_timeout` retryable. Host disconnect fails pending requests with retryable `browser_no_host`.
- Wire: host registers with `browser.host.register.request {requestId, hostKind, supportedCommands}` -> `browser.host.register.response {requestId, subscriptionId}` (owned subscription kind `browser-host`; `session.ts:2351`; legacy capability-based registration for old clients `session.ts:1323`, requires `workspace.write`); daemon pushes `browser.automation.execute.request {subscriptionId?, requestId, agentId?, cwd?, workspaceId?, command{command,args}}`; host answers with `browser.automation.execute.response {payload:{requestId, ok:true,result,dialogs?} | {requestId, ok:false,error{code,message,retryable},dialogs?}}` (`session.ts:2421`, only accepted from the subscription's own source). ## Cross-area connections
- Agents/sessions: agent tools (`create_terminal`, `capture_terminal`, `send_terminal_keys`, `list_workspace_scripts`, `start/stop_workspace_script`, `browser_*`) registered in `paseo-tools.ts`; agent workspace decides terminal workspace; `agentId` terminals rejected on create; hooks for Claude/Codex/OpenCode feed terminal activity; browser tool calls carry `agentId/cwd/workspaceId`.
- Workspaces/projects: terminals and scripts keyed by `workspaceId`; archive teardown (`killTerminalsForWorkspace`, runtime store removal, port plan release); worktree creation runs `worktree.setup` then `worktree.terminals`; branch rename re-routes service hostnames; workspace descriptor carries `scripts[]` and terminal activity roll-up status; project settings editor writes `paseo.json` scripts; daemon `worktrees.servicePorts`.
- Host/daemon: daemon config keys `browserTools.enabled`, `enableTerminalAgentHooks`, `terminalProfiles`, `serviceProxy.{listen,publicBaseUrl}`, `worktrees.servicePorts`, env `PASEO_SERVICE_PROXY_*`; terminal worker lifecycle tied to daemon stop/restart (`keepTerminals`); loopback `/api/terminal-activity`; express mount order (service proxy before auth/host allowlist); WS upgrade sharing; server info `features` flags for terminal capabilities.
- Notifications/attention: `terminal_attention_required` -> OS/push notifications, `computeNotificationPlan` with client presence heartbeat (`focusedTerminalId`), sidebar status buckets.
- Attachments/composer: browser "annotate element" adds `browser_element` attachments to the composer; terminal file paste/drop uses `client.uploadFile` (file upload RPC, 50 MiB limit); terminal drop uses desktop host bridge (`webUtils.getPathForFile`).
- Files/explorer: terminal local file links open file tabs (main or side); explorer sidebar is a pane host (`explorer`) that also accepts terminal tabs; mobile file explorer drawer.
- Settings: `terminalScrollbackLines`, `monoFontFamily`, `codeFontSize`, `serviceUrlBehavior`, host terminal profiles, host agent-hooks and browser-tools switches, Browser data clear, keyboard shortcut registry (`keyboard/keyboard-shortcuts.ts`, `terminal:false` contexts).
- Providers/models: terminal profiles reuse provider icon names (`provider-icon-names.ts`); OpenCode helper processes use the managed-process ledger.
- CLI: `paseo terminal *`, `paseo script *`, `paseo hooks` (activity reporter).
- Relay/transport: terminal binary frames and snapshots over the multiplexed relay (no bufferedAmount signal -> byte-threshold fallback); `terminal_chunked_replay` capability negotiation.
- Plugins: plugin panels are another tab kind in the same layout system; plugin panels/workspace targets share `WorkspaceTabTarget`.
- Command center/launcher: new-tab launcher builds terminal/profile/browser entries; `workspace-terminal-new` and tab shortcuts.
