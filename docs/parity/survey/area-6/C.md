## Workspace list: grouping, filtering, sorting, pinning

### What the user sees
Scrollable list (`ProjectModeList` for project grouping, `SidebarStatusWorkspaceList` for status grouping; testIDs `sidebar-project-workspace-list-scroll`, `sidebar-status-list-scroll`) under a "Workspaces" section header (`left-sidebar.tsx:803`, literal English title, tooltip "Display preferences") with the display-preferences menu button. Above the groups: a collapsible **Pinned** section (`sidebar-pinned-section`, header title key `sidebar.pinned.title`) containing pinned workspaces (individually pinned chats hoisted out of their project/status group).
- Empty states (`components/sidebar/empty-states.tsx`): no projects → `sidebar-project-empty-state` with buttons Add project (`sidebar.actions.addProject`) and Import session (`importSession.title`); filters hid everything → `sidebar-filter-empty-state` with Clear action.
- "Show more/less" rows (`SidebarGroupToggleRow`): per project (`sidebar-project-show-more-<viewKey>`), pinned (`sidebar-pinned-show-more`), per status group (`sidebar-status-group-show-more-<bucket>`).

### How it works
- Data: `useSidebarWorkspacesList` (`hooks/use-sidebar-workspaces-list.ts:99`) picks hosts (all, or `hostFilters` intersect known; falls back to all once registry loaded and none match), acquires directory demand per host (`runtime.acquireDirectoryDemand`), builds projects with `useWorkspaceStructure(serverIds, sort)`, writes missing keys back to `useSidebarOrderStore`, exposes `workspaceSortSupported` = every host has feature `workspaceSortTimes`. `sort` is applied only if groupMode is `project` and (`workspaceSort==="manual"` or supported).
- Project merging across hosts: `projects/workspace-structure.ts buildWorkspaceStructureProjects`: projects with the same `projectKey` (equivalence key) on different hosts merge into one view (`viewKey = projectKey`, or `JSON.stringify([serverId, projectId])` placement key, with collision-suffix keys). Projects sorted by name (`localeCompare`, numeric, base). Project name = `projectCustomName ?? projectDisplayName ?? derived from projectId`.
- Workspace order inside a project: `compareWorkspaceStructureItems` (name, numeric) when no sort; `created` = `createdAt` desc; `lastPrompt` = `lastUserMessageAt ?? createdAt` desc (`workspace-structure.ts:208-231`). Type `WorkspaceSort = "manual" | "created" | "lastPrompt"` (`:33`).
- `SidebarModelProvider` (`components/sidebar/sidebar-model.tsx:51`): composes list + filters + projection. Order: host filter (list hook) → project filter (`resolveActiveProjectFilters`/`filterWorkspacesByProjects`) → background hiding (`workspace.background` hidden unless `showBackground`) → label filter (`filterWorkspacesByLabels`; any-of; key `""` = Unlabelled, `SIDEBAR_UNLABELLED_LABEL_KEY`) → drop empty projects (a project filtered TO survives with 0 workspaces; label filter empties drop projects) → `usePinnedSidebarKeys` → `buildSidebarProjection`. Workspace entries are only hydrated when `active !== false || groupMode !== "project" || label filter active`.
- Projection (`components/sidebar/sidebar-projection.ts`): splits pinned (`splitPinnedSidebarGroups`: pinned sorted by `pinnedAt` desc then `applyStoredOrdering` with `pinnedWorkspaceOrder`), builds status groups for unpinned workspaces in status mode, and the keyboard shortcut model (Pinned first unless collapsed, then projects or status groups, skipping collapsed sections).
- Grouping modes `SidebarGroupMode = "project" | "status"` (`stores/sidebar-view-store.ts:9`). Persisted schema also accepts `"label"` but `migrateSidebarViewState` maps anything but `"status"` to `"project"`.
- Status grouping (`hooks/sidebar-status-view-model.ts`): bucket order `STATUS_BUCKET_ORDER = needs_input, failed, attention, running, done` (`utils/sidebar-agent-state.ts:36`); labels keys `sidebar.statusBucket.{needsInput,failed,readyToReview,working,done}` (attention = "ready to review", running = "working"). Rows in a group sort by `statusEnteredAt` desc (rows without time after rows with), then project name, workspace name, workspaceKey.
- Bucket derivation (`packages/protocol/src/agent-state-bucket.ts deriveAgentStateBucket`): `needs_input` if pendingPermissionCount>0 or attentionReason "permission"; `failed` if status "error" or attentionReason "error"; `running` if status "running"; `attention` if requiresAttention; else `done`. Collapsed-project aggregate uses `STATUS_BUCKET_PRIORITY = needs_input, failed, running, attention, done` (running outranks attention there) (`utils/sidebar-agent-state.ts:23`).
- "Show more" limits (`components/sidebar/sidebar-group-visibility.ts:461`): limit **20** for pinned, **7** for workspace groups; in workspace groups any workspace whose bucket is not `done` is always in the baseline; the open (selected) workspace hidden by the limit is rendered first as `leadingItem`. State is local `useState` (`use-limited-sidebar-group.ts`), not persisted.
- Collapse state: `stores/sidebar-collapsed-sections-store` (persist name `"sidebar-collapsed-sections"`): `collapsedProjectKeys: Set`, `collapsedWorkspaceGroupKeys: Set`, `collapsedPinned: boolean`; actions `toggleProjectCollapsed`, `toggleWorkspaceGroupCollapsed`, `togglePinnedCollapsed`, `setProjectCollapsed`.
- Manual order: `stores/sidebar-order-store.ts` (persist name `"sidebar-project-workspace-order"`, version 3): `projectOrder`, `pinnedWorkspaceOrder`, `workspaceOrderByProject[projectViewKey]`; keys deduped (`dedupeKeys`, not trimmed). Project order always applies (project drag always enabled); per-project workspace order only drags when `workspaceSort === "manual"` (`manualSort` prop).
- View store `stores/sidebar-view-store.ts` (persist name `"sidebar-view"`, version 8, legacy key `"sidebar-group-mode"`): `groupMode` default `project`, `workspaceSort` default `created`, `showBackground` default false, `hostFilters: string[]` (empty = all), `projectFilters: string[]` (viewKeys; stale keys are ignored at read time, never deleted), `labelFilter {labels: string[]}` (reconciled against the label catalog when authoritative).
- Pin/unpin: client `setWorkspacePinned(workspaceId, pinned)` (`packages/client/src/daemon-client.ts:3517`) → message `workspace.pin.set.request {workspaceId, pinned, requestId}` (`packages/protocol/src/messages.ts:1034`) → `server/src/server/session.ts:3945-3985`: updates `workspaceRegistry` with `pinnedAt = ISO now | null`, replies `workspace.pin.set.response {requestId, workspaceId, accepted, pinnedAt, error}`, then `emitWorkspaceUpdatesForWorkspaceIds`. Permission `workspace.manage` (`authorization/operation-permissions.ts:217`). App controller `hooks/use-sidebar-workspace-pin.ts`: module-level `pendingWorkspaceKeys` set blocks double toggles; error toast, `sidebar.workspace.toasts.hostDisconnected` when no client. Gated by host feature `workspacePinning`.
- Host badges: `useHostBadges({enabled: rowItems.host && shouldShowSidebarHostLabels(projects)})`; per-host `badgeDisplay` decides name/icon/hidden.

### States, errors, defaults
Display preference settings (synced app settings, `hooks/use-settings/storage.ts`): `workspaceTitleSource` `"title"|"branch"` default `"title"`; `sidebarWorkspaceTrailing` `"diff"|"timestamp"|"none"` default `"timestamp"`; `sidebarRowItems` default `{branch:false, project:false, host:true, changeRequest:true, services:true, labels:true}`; `sidebarChecksDisplay` `"iconAndText"|"icon"|"none"` default `"iconAndText"`.

## Keyboard shortcuts: engine, bindings, dispatch

### What the user sees
Desktop/web only (`keyboardShortcutsAvailable` = `!isNative && !isCompact`, `keyboard/availability.ts`). Shortcut hints appear as chips in tooltips, sidebar rows, command center rows and Settings > Shortcuts. Holding the workspace-jump modifier shows numeric badges 1-9 on sidebar workspace rows. A help dialog lists all shortcuts and searches them.

### How it works
- Entry: `hooks/use-keyboard-shortcuts.ts useKeyboardShortcuts` mounted in `app/_layout.tsx:418` (`enabled: chromeEnabled || pathname.startsWith("/settings")`). Capture-phase window `keydown`/`keyup` listeners, `blur` and `visibilitychange` reset modifiers. Skips when: document not visible; `dispatchTopWebOverlayKeyDown` consumed it; key belongs to a DOM popover; IME composing (`isImeComposingKeyboardEvent`); a shortcut is being captured in Settings (`capturingShortcut`); Escape on a wide `/settings` page with an overlay open.
- Resolution pipeline: DOM event → `resolveKeyboardFocusScope` → `resolveKeyboardShortcut({event, context:{isMac,isDesktop,focusScope,commandCenterOpen}, chordState, bindings})` (`keyboard/keyboard-shortcuts.ts:1549`) → `KeyboardShortcutMatch {action, payload, preventDefault, stopPropagation}` → `routeKeyboardShortcut` (`keyboard/route-shortcut.ts`) → `ShortcutAction` → `performShortcutAction` (dispatch / navigate / router / callback / command center / dialog). On handled it calls `preventDefault()`/`stopPropagation()` per binding (defaults true,true). In workspace focus mode, a handled `sidebar.*` action also calls `exitFocusMode()`.
- Electron browser panel: key events from embedded browser webviews arrive as desktop event `browser-shortcut-input` and resolve with focus scope `"browser"`; the app publishes a shortcut policy to the desktop host (`getDesktopHost().browser.setShortcutPolicy({menuPrefixes, prefixes})`, `buildBrowserKeyboardPolicy` in `desktop/browser/shortcuts`) so the host can intercept prefixes (including in-progress chords).
- Binding model (`keyboard-shortcuts.ts:259` `SHORTCUT_BINDINGS`, 76 entries): `{id, action, combo, repeat?:false, when?, payload?, preventDefault?, stopPropagation?, help?}`. `when` (`ShortcutWhen`): `mac` (true mac only, false non-mac only), `desktop` (true Electron only, false web only), `editable:false` (not while focus scope is `message-input` or `editable`), `terminal:false` (not in terminal), `commandCenter:false` (not while command center open), `focusScope` (allowed scope or list). Payload kinds: `{type:"index"}` (digit 1-9 via `Digit` wildcard, accepts `Digit1-9`, `Numpad1-9`, key "1"-"9"), `{type:"delta", delta:±1}`, `{type:"message-input", kind}`.
- Combo string format (`keyboard/shortcut-string.ts`): modifiers `Cmd` (meta), `Ctrl`, `Alt`, `Shift`, `Mod` (Cmd on mac / Ctrl elsewhere) joined by `+`, then one key name; chords are space-separated combos (e.g. `"Cmd+K Cmd+S"`). Key names (`KEY_MAP`): A-Z, 0-9, `Digit` (wildcard for 1-9), `- = \ [ ] ; ' , . ` /`, `?`, `Space`, `Enter`, `Backspace`, `Escape`, arrows `ArrowLeft/Right/Up/Down`, `Tab`, `Delete`, `Home`, `End`, `PageUp`, `PageDown`, `Insert`, `F1`-`F12`. Matching is key-first (logical character; Dvorak-friendly), with fallbacks: shifted key, physical code for non-Latin letters, `Alt` + code (macOS rewrites key under Option), `codeFallback` for Space/Enter.
- Chords: `CHORD_TIMEOUT_MS = 1500` (`keyboard-shortcuts.ts:1386`). First step with multi-combo candidates swallows the event (preventDefault) and starts a timer; later steps narrow candidates; modifier-only keydowns are ignored (`isModifierKeyCode`). No default binding is a chord; only user overrides can be.
- Overrides: `ShortcutOverrides = Record<bindingId, string | null>`; `null` (`UNASSIGNED_COMBO`) = user unassigned (no keys), absent = default, `""` also means no keys. `buildEffectiveBindings(overrides)` (`:1228`) replaces combos; an override drops the default `editable:false` guard (`withoutDefaultComboGuard`) and `defaultDisplayKeys`; unparseable override falls back to default. Override ids keep legacy names on purpose (e.g. `agent-new-cmd-shift-o-mac` is now `Cmd+O`).
- Override persistence: AsyncStorage key `@paseo:keyboard-shortcut-overrides` (zod `record(string, string|null)`), react-query key `["keyboard-shortcut-overrides"]` (`hooks/use-keyboard-shortcut-overrides.ts`). `createShortcutOverrideStore` (`keyboard/shortcut-override-store.ts`): optimistic cache, serialized write queue, rollback on failure; ops `set`, `clear` (assign null), `remove` (drop override), `resetAll`. Per-device only, not synced to the daemon.
- Display: `resolveShortcutKeysForAction(actionId, overrides, platform)` (`:1638`) is the single resolver for hint chips (`hooks/use-shortcut-keys.ts useShortcutKeys(helpId)`), command center, Settings; `chordStringToShortcutKeys` turns `Cmd`/`Mod` into the platform "mod" key. `getShortcutOs()` (`utils/shortcut-platform.ts`): native iOS = mac, Android = non-mac, Electron mac = mac, else user-agent sniff.
- Action dispatcher (`keyboard/keyboard-action-dispatcher.ts`): `createKeyboardActionDispatcher()` keeps `Map<handlerId, handler>`; `dispatch(action)` filters handlers by `actions.includes(id)`, `enabled`, `isActive()`, sorts by `priority` desc then most-recent registration first, calls `handle(action)` until one returns true (returns boolean). `useKeyboardActionHandler({handlerId, actions, enabled, priority, isActive?, handle})` (`hooks/use-keyboard-action-handler.ts`) registers once per handlerId/priority/actions, reads latest callbacks from a ref. `buildWorkspaceKeyboardHandlerId({name, serverId, workspaceId, paneId?})` = `name:serverId:workspaceId[:paneId]` (`keyboard/handler-id.ts`) because a duplicate id evicts the earlier handler. Dispatcher scope field: `"global" | "message-input" | "sidebar" | "workspace"`.
- Handlers found registering with `useKeyboardActionHandler` (grep): `panels/new-tab-panel.tsx:229`, `components/sidebar/sidebar-workspace-row.tsx:141`, `components/sidebar/sidebar-status-list.tsx:702`, `components/sidebar-workspace-list.tsx:1317` (workspace.archive for the selected row), `components/workspace-rename-host.tsx:67`, `screens/workspace/workspace-desktop-tabs-row.tsx:1261`, `composer/agent-controls/mode-control.tsx:152`, `composer/index.tsx:619`, `hooks/use-active-worktree-new-action.ts:32`, `screens/new-workspace-screen.tsx:1189`, `hooks/use-global-workspace-pin-action.ts:57` (workspace.pin, handlerId `workspace-pin-global`, mounted via `components/workspace-pin-shortcut-handler.tsx`), `hooks/use-global-new-workspace-action.ts:46`, and eight in `screens/workspace/workspace-screen.tsx` (2735-2866; includes `sidebar.toggle.right`/`sidebar.toggle.both` at 2855).
- Focus scopes (`keyboard/focus-scope.ts resolveKeyboardFocusScope`, type `KeyboardFocusScope` in `keyboard/actions.ts`): `terminal` (target inside `[data-testid='terminal-surface']` or `.xterm`), `command-center` (command center open and target in `command-center-panel`/`command-center-input`, or any other input while open), `message-input` (inside `[data-testid='message-input-root']`), `editable` (contenteditable/input/textarea/select), `browser` (only from the Electron webview path), `other`.

### How it works
- State: `useKeyboardShortcutsStore` holds `commandCenterOpen`, `commandCenterScope: "files" | null` (`stores/keyboard-shortcuts-store.ts`). Focus is restored on close to the element captured at open (`utils/command-center-focus-restore`, `focusWithRetries`); if restore times out it dispatches `message-input.focus`.
- Registry (`command-center/registry.ts`, `provider.tsx`): `createCommandCenterRegistry()` holds registrations keyed by `owner.sourceId`; each has `contributions[]`. Ids become `<sourceId>:<id>`; duplicate ids throw `Duplicate Command Center contribution id`. Snapshot sorted by `groupRank`, then `group` name, then `rank`, then id. `useCommandCenterActions({sourceId, enabled, actions})` registers/removes (owner token guards against a stale cleanup). `useCommandCenterContributions()` reads the snapshot via `useSyncExternalStore`.
- Contribution shape (`command-center/contributions.ts`): `{id, group, groupRank, rank, keywords[], visibility: "always" | "query", run(), presentation}`; presentation kind `action {title, subtitle?, sectionTitle?, icon?, shortcutKeys?}` or `choice {path: [string,...], icon?, selected, testId?}`. `visibility "query"` rows only appear once the user has typed something.
- Projection: sections = contribution sections (band 0, ordered by `groupRank` with no query; by best match score with a query) then pinned sections (band 1) ordered by `rank`: `workspaces` (rank 2), `agents` (rank 3), `files` (rank 4). In files scope only the files section. `projectCommandCenterRows` turns sections into rows with a divider between sections and a title row where the section has one.
- Matching (`results.ts`): `scoreSearchFields(query, {visible, hidden})` uses `scoreTextFields` from `packages/protocol/src/search/text-match.ts`: tokens split on whitespace, each must match some field; tiers `EXACT 0, WHOLE_WORD 1, PREFIX 2, WORD_START 3, SUBSTRING 4, SUBSEQUENCE 5 (within one word), FUZZY 6` (fuzzy off here). Field rank: all tokens matched visible text = 0, needed a hidden keyword = 1; field rank is compared before match quality. Built-in rows (workspace, agent) rank by `compareBuiltInScores` (field rank, then tier) then recency (`activityAt` desc); with an empty query each built-in category shows the 5 most recent (`DEFAULT_CATEGORY_RESULT_LIMIT = 5`). Workspace query also matches change-request numbers: regex `/^(?:(?:pr|mr)\s*)?[#!]?(\d+)$/i` (`42`, `#42`, `!42`, `pr 42`, `PR #42`, `mr!42`) puts exact `changeRequestNumber` hits first (`command-center/workspace-search.ts`). Agent rows also match their hidden `cwd`.
- Built-in data: `useAggregatedAgents({demand: open})` (all hosts' agents), `useProjects({enabled: open})` (workspaces with `archivingAt` skipped); callbacks navigate with `navigateToWorkspace` / `navigateToAgent`. Everything is built only while open.
- File search (`workspace-file-search.ts useWorkspaceFileSearch`): enabled when open and (scope files or non-empty query), active workspace required. Client `getDirectorySuggestions({cwd, query, includeFiles:true, includeDirectories:false, limit: FILE_SEARCH_LIMIT = 100})` (`packages/client/src/daemon-client.ts:5139`) → message `directory_suggestions_request {query, cwd?, includeFiles?, includeDirectories?, matchMode?: "fuzzy"|"suffix", limit? (1-100), requestId}` (`packages/protocol/src/messages.ts:2561`) → server `Session.handleDirectorySuggestionsRequest` (`packages/server/src/server/session.ts:5221`): `searchDirectoryEntries` with `root = cwd`, relative paths, `respectGitIgnore: true` for workspace searches, hidden directories only if in `WORKSPACE_SEARCH_HIDDEN_DIRECTORIES`; replies `directory_suggestions_response {directories, entries, error, requestId}`. Debounce `FILE_SEARCH_DEBOUNCE_MS = 100` for non-empty queries (0 for empty); stale responses discarded; previous entries kept while a new query loads in the same workspace. Selecting a file → `openWorkspaceFileFromExplorer` + `useWorkspaceLayoutStore.openTab({target, intent:"reveal", placement})` + `revealWorkspaceTab`.
- Selection/scroll model `command-center/interaction.ts createCommandCenterInteraction`: selection (activeId) persists across projection updates (`preserveActiveResultId` falls back to first result); selection resets when opening or changing scope; moving selection reveals the row once per user command; manual scroll/touch/wheel cancels pending reveal; arrow keys do nothing while scoped file search is loading.

### States, errors, defaults
Loading file search shows no empty text; errors show `common.errors.error: <message>` (DaemonRpcError suffix ` requestType=... code=...` stripped). A registry duplicate id throws at registration time. Wide layout shows no bottom sheet; shortcut chips hidden when shortcuts unavailable.

### Platforms
Web/desktop: modal + keyboard model above. Compact native: bottom sheet (`showBottomSheet = isCompact && isNative`), input focus delayed 300 ms. Pane actions web only; browser tab action Electron only.
