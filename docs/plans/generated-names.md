# Generated names

ADR 0062 is the contract. This file is the reading notes, the reuse
decision, and the slice list. The protocol threshold is the optional
`GENERATED_NAMES`, assigned at merge. Neither document chooses it.

## Stated differences

ADR 0062 records each one with its reason. Short form:

1. One upstream completion, retries 0, the first resolvable route only.
   Paseo retries twice and walks the list.
2. `vessel-llm` on a route, not an internal agent.
3. 20 seconds for the whole call. Paseo has no such clock.
4. 16 384 characters of source. Paseo sends the whole prompt, 120 000
   characters of a commit patch, or 200 000 of a pull-request patch.
5. A `typed` title is never replaced. Paseo also replaces a workspace
   title that merely equals the prompt line. An `unknown` origin (a
   title stored before `GENERATED_NAMES`) is not replaced either.
6. `text.commit` and `text.pull` return text. `git.commit` and `pr.open`
   do not call a model. Paseo generates inside the checkout call.
7. The pull-request body fallback is `Opened from this branch.`, not a
   sentence that names Paseo. The commit fallback `Update files` and the
   title fallback `Update changes` stay.
8. Instructions are read from disk at the repository root, as Paseo
   reads `paseo.json`. The file is `vessel.toml`, and the keys are
   `[metadata.title]`, `[metadata.branch]`, `[metadata.commit]` and
   `[metadata.pull]`, the names ADR 0066's table already assigns to
   this decision. Paseo's keys are `metadataGeneration.title`,
   `branchName`, `commitMessage` and `pullRequest`. Each instructions
   string is at most 1 024 characters; Paseo has no such bound. A
   legacy `agentTitle` is ignored, as 0066 says and as Paseo only keeps
   the key so an old file parses. 0066 does not parse these tables and
   does not put them in the command digest.
9. A generated body is at most 4 096 characters. Paseo's schema has no
   maximum.
10. No matching route means no call. Paseo can ask the agent's own
    provider without a route file.
11. The generated words are a **session** title (`SessionInfo.title`),
    once per new structured session that had no `spec.title`. Paseo's
    generated words are a **workspace** title, once per created
    workspace. Reason: the board reads the session's title, and Vessel
    has no workspace title. Cost: four such sessions in one worktree
    are four calls here and one there; twenty in a day are twenty
    calls, each still one route, 16 384 characters and 20 seconds.
12. A branch rename is not pushed. Paseo notifies
    (`notifyGitMutation` `rename-branch`, `emitWorkspaceUpdateForCwd`,
    `workspace-auto-name.ts` 149–152). The session title is pushed, as
    the `renamed` event a follower already applies. A screen sees the
    new branch on its next read of the worktree.
13. The automatic match is case-insensitive on the model id, the
    `small_model` id and the route name. Paseo matches the model id and
    its label. `ModelRoute` has no label; the route name stands in for
    it.
14. A manual list is deduped (same route, model and effort; the first
    stays). An effort the provider's API cannot say is omitted at the
    call and the provider's default is used: Anthropic's wire has no
    `minimal` (`wire/anthropic.rs` 376–385). An effort outside the enum
    is refused when the setting is written. Paseo passes explicit-model
    manual candidates through on top-level providers (136–160); omitted
    models use the default or first model and resolve thinking against it
    (162–169, 259–276). Vessel validates the allowed route/model pair and
    closed effort before saving. Preferring an omitted model's `small_model`
    is a Vessel cost choice, not Paseo's default/first-model rule.
15. The ADR 0022 constructors stay: a provisional title is cut at 80
    Unicode scalar values and a typed title allows 120. Internal prompt
    whitespace is retained, with control characters replaced by spaces.
    Paseo collapses whitespace and uses JavaScript's UTF-16 slicing at 60;
    its explicit bound is 200 UTF-16 units (`create-agent-title.ts` 4–18,
    `agent-title-limits.ts` 1). Preserving the existing constructors keeps
    new prompt-derived names consistent with earlier Vessel sessions and
    keeps the wire's accepted title set stable.

## What a screen calls

These calls are the whole of what a screen needs. This change draws
nothing.

- **The settings section** reads `node.settings` (`read`) and writes
  `node.set_settings` (`admin`). The field is `metadata.providers`: an
  array of `{ route, model?, effort? }`, bounded by `MAX_METADATA_PROVIDERS`. Empty, present,
  is automatic. Absent `metadata` means the peer does not generate
  (below `GENERATED_NAMES`); the section is not offered as if it worked.
  Send `metadata` only when the peer speaks that constant. `effort` is
  `minimal`, `low`,
  `medium`, `high` or `max`. The routes to offer come from `model.list`.
- **A session's title** needs no new call. `SessionInfo.title` is still
  the words. `SessionInfo.title_origin` is `typed`, `given`, `generated`
  or `unknown` (absent is `unknown`). The same origin is on each
  `renamed` event. A screen keeps showing `title`. It does not ask for a
  title to be generated, and it does not hide a `given` title while a
  generation might still replace it.
- **A branch** needs no new call. `git.rename_branch` updates the
  stored worktree (`branch` and `created_branch`) and does not push.
  A screen sees the new name on its next read of the worktree. This
  change adds no event.
- **Commit and pull-request text**, when those screens exist, call
  `text.commit` `{ root }` and `text.pull` `{ root, base? }` (`operate`,
  `since` = `GENERATED_NAMES`, the number given at merge). The answer
  is the text plus `source`:
  `generated` or `fallback`. The screen then calls `git.commit` or
  `pr.open` with that text. It does not omit the message and expect
  either of those to fill it.
