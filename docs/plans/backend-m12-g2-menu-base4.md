# Shared action menu on package base4

Priority: provide G1 the integrated producer before the F1 remainder. Base is
3cd0d3fc; the published single menu renderer, menu_right TopRight, QUICK appear,
fill_in and input ordering are retained. Historical f667 split and ef91 typed
restore were source/A13 cleared on their old bases; this range needs its own
narrow checks and V1 source review. Their prior gates are not new-base proof.

[Decision Log]
- Purpose: direct Git writes keep pending/success feedback in one open menu.
- Constraint: the lead's renderer remains authoritative; no historical second
  renderer, raw menu chain, alternate motion or area spinner is introduced.
- Alternatives: reusing the old branch wholesale or close/reopen area workarounds.
- Choice: additive typed item feedback, muted presentation,14/16 leading size,
  dismissal and measured-end placement on that one renderer, with named placement.
- Why: existing constructors/entry signatures/default Close and leading14 remain;
  each consumer opts into its reference states rather than painting local rows.
- Cost: ordinary public struct literals must use the existing constructors for
  additive defaults; exact untouched base callers are checked in the integration.

References: pinned Paseo1c00b365 components/ui/menu/menu-item.tsx (whole),
menu-root.tsx (whole), git/actions-split-button.tsx (whole), git/action-icons.tsx
(whole), components/schedules/schedule-row.tsx (whole), control-geometry.ts.
Pending and success are nonselectable, opacity0.5,feedback16 in slot16. Success
uses the incoming canonical GREEN_500 and existing CircleCheck. Muted idle stays
selectable with foregroundMuted and0.72 opacity. Disabled/feedback take priority.
Normal leading defaults14; with_leading_at(...,Regular) opts into16. KeepOpen
keeps pointer/Enter/Space actions on the same surface; stale keyboard indices
and feedback rows cannot activate. Width is optional; open_end uses actual inner
trigger bounds. Legacy point/menu_right placement and screen priority1 remain.

The Schedule and GitHeader trigger profiles preserve source geometry. The shared
canonical touch-target path replaces the missing old popup alias without a
value change. Source geometry/hit tests do not prove actual hit dispatch, clipping
or parent/neighbor precedence. ProviderRow, modal layer and passive spacer remain
separate requests and are not implemented by this range.

Weak opener restoration and its actual window-key regressions are included as
current source, not an assertion that historical Linux F5 HOLD is settled. G4
owns the forthcoming generic ReturnFocus helper; the private menu implementation
will consume that reviewed helper instead of creating another generic primitive.
No dialog renderer is edited. Linux first-use/input captures, new-base UI and
all consuming Git/F1 behavior remain unverified until their feature packages.
