# Offline VAD dependency proof — A1 only

The coordinator selected A1 in package ADR0080: exact ort2.0.0-rc.15,
defaults off, only std/load-dynamic/api-28. The default native downloader is
rejected. This isolated leaf starts at announced node9c150c6e and changes only
workspace/node DEV manifests plus candidate notices/documentation; it brings
no voice actor, RPC change, model/native file or API invocation.

[Decision Log]
- Purpose: obtain an offline lock/feature/compiler receipt on the current base
  before adopting any loader or running the pinned Silero model.
- Existing assets: the reviewed six-crate/version/archive table and complete
  candidate notices already exist; the old82 scratch resolve failed because
  ort was absent. Its unchanged lock/empty tree qualify no current graph.
- Choice: T provisions only exact approved sparse records/archive bytes, then
  runs a fixed offline scratch resolution for this immutable current-base head.
- Why: disable-linking returns before native lookup/download/copy/linking;
  adding a DEV dependency provides compile proof without a product backend.
- Impact: no Cargo/build script until V3 accepts the actual lock/features. No
  runtime constructor/model API, active provider, download or distribution.

Provisioning is limited to ort2.0.0-rc.15, ort-sys2.0.0-rc.15 and libloading0.9.0.
Existing smallvec1.16.4/cfg-if1.0.5/windows-link0.2.1 must match the pinned table;
no cache refetch or extra version/dependency/feature. Sparse records, registry
checksums and archive bytes need one receipt. Never copy credentials/config.
The node consumes only ort as a DEV dependency; workspace product edges stay
unchanged. Complete byte-pinned candidate licences are under docs/notices/voice-vad.

Required order: coordinator-approved provisioning; fixed offline scratch
resolve, Cargo.lock diff and full feature tree; V3 receipt acceptance; separately
reviewed offline Linux and Windows MSVC compilation on the build VM. Verify
sys/disable-linking plus std and API17..28, wrapper/preload-dylibs and no
feature expansion. DOCS_RS cannot stand in for a verified feature branch.
No public API or code on this leaf calls ort. Windows compilation requires the
approved SDK/target but no ORT import library/DLL at binding-build time.
Actual compiler/link evidence, native allocation/size and runtime privacy are
still owed. Loader/library/model execution and packaging remain later reviews.

Tract remains the documented fallback only if A1 fails a Windows build/load,
32ms p99 window budget or installer-size gate. It is not provisioned here.
This leaf does not turn an unmeasured benchmark into an approval or fetch it.
