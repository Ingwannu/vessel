# C3 original shown-source command projection

Status: installed source only; uncompiled/unexecuted. This is not a write-owner
handoff, F4 reactivation, UI-visit authority or full C3 acceptance.

## Existing assets and responsibility

The announced base14.3 contains C5's ONE guarded root/summary acquisition and
its opaque ShownChangesContext. Git already owns the toolbar/palette intention
projection and pure logical menu selection. Reuse these assets; no source
registry, resolver, ticket generator, transport, controller or external package
is added. W13 confirmed no competing shown_source writer and authorized the
small identity-only method with this real consumer.

ShownChangesContext::same_source compares original root context/session/ticket,
FileScope, summary ticket and comparison. It deliberately ignores guard identity
and liveness: retired clones remain the same acquisition. The existing
shown_changes_is_current behavior is unchanged and still checks the original
live actor proof and current owner. Opaque fields remain private.

GitCommandTarget now captures that SAME receipt when the menu contribution is
built. Its equality combines immutable source identity and the existing logical
repository/generation/session/PR intention, so an equal-byte refreshed summary
changes the contribution fingerprint without inventing a new id. Activation
rechecks the captured original receipt before looking up live availability.
It never substitutes a new receipt from the same path for an old callback.
The pure logical rules remain separately testable without fabricated guards.

Only ShownChangesContext and its connection/root/getter/currentness entry points
are promoted from test staging for this caller. Diff and typed Explorer helpers,
retirement delegation and comparison accessor retain their existing staging.
The source producer's node/selected/delivery/actor implementation is unchanged.

## Behavioral change and limits

An unstamped toolbar no longer offers a command projection. A refreshed summary
or expired original admission refuses its retained callback even when logical
repository/generation are equal. Current valid contributions still delegate the
one existing menu policy. ALL mutations continue through origin's explicit
unverified refusal: this change allocates no write key, sends no mutation and
reactivates no F4 source.

Legacy toolbar status still lacks the scoped status-read owner. The new main
C3 read transport also needs the existing DeliveryGuard retained through queue
installation/getters before it can serve future write authority; a copied
ConnectionContext alone does not close that gap. Original UI visit/dialog
occurrence, original G4 mutation preflight and retained sent/uncertain lifecycle
remain required. Do not enable writes over git_follow's disposable legacy
pending fields or create an anonymous receipt side map.

[Decision Log]
- Purpose: prevent source refresh or connection retirement from silently
  upgrading an old menu/palette callback, while retaining one policy path.
- Constraint: opaque C5 proof is not an action approval, UI visit or RootLease.
  Equality cannot validate liveness; currentness cannot replace captured intent.
- Alternatives: copy source fields into Git, mint another fingerprint id, compare
  paths/counts, or look up a fresh source at press. All duplicate or lose facts.
- Choice: one owner-local acquisition equality method plus original receipt in
  the existing command target, with currentness checked separately at callback.
- Why: reuses actual source lifetime and canonical guards without exposing a
  capability constructor or adding another registry. Existing pure intention
  tests remain pure; actual source tests use framed Scenario responses.
- Cost: unstamped projections are unavailable until a real stamped acquisition.
  Scope/instance/confirmation/write lifetime work remains a separate mandatory
  join, not approval implied by this smaller prerequisite.

## Required receiving checks

The new framed identity fixture checks clone, root/summary tickets, session,
physical scope, comparison and root context; a real same-node reconnect retires
both original clones while same_source remains true. The real command fixture
captures a ready receipt, refreshes it through actual GetChanges frames and
proves the old callback cannot dispatch before or after the successor appears.
Its menu availability input is explicitly synthetic, not authenticated status
or successful-write evidence. Transcript must contain only root/summary calls.
All are unexecuted until the exact changed-source receiving selection completes.
