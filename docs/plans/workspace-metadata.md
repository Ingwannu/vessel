## Asset and reuse decision

[Decision Log]
- Purpose: share routing, credential policy and accounting without treating a
  workspace request as session title work.
- Existing assets: Models' node semaphore, catalog and key reader; shared
  provider options, complete request/reply API, initialized TLS and neutral
  accounting; canonical workspace/root operation ids and checked root snapshots.
- Decision: modify Models by adding a workspace purpose, reuse those owners,
  and add a transient bounded report owner because the existing durable ledger
  is session-oriented and does not project ModelCall as workspace accounting.
- Alternatives: temporary/borrowed sessions, a copied provider stack and title
  private-module exports are refused. The standard owned task/token, semaphore
  permit and bounded container types suffice; no dependency is needed.
- Consequences: title behavior is frozen; root reports explicitly distinguish
  reported and unavailable usage and survive requesting-future cancellation.
  No durable workspace history, platform or real-provider proof is claimed.
