# Ten agents set up as Paseo sets them up (ADR 0058)

The owner asked for ten agents set up exactly as Paseo sets them up: Codex,
Claude Code, Grok, OpenCode, Pi, Oh My Pi (OMP), Antigravity, Muse Code, Amp
and Cursor. ADR 0058 decides the shape; this plan is the order of work.
Paseo references are to `getpaseo/paseo` at tag `v0.15.4`, with these
shorthands: `PR` = `packages/server/src/server/agent/providers`, `REG` =
`packages/server/src/server/agent/provider-registry.ts`, `MAN` =
`packages/protocol/src/provider-manifest.ts`, `PL` = `plugins`.

## 0. Findings that change the starting picture

1. **The ACP registry has first-party entries** (v1.0.0, 46 agents, read
   2026-11-14): `grok-build` (xAI, `npx @xai-official/grok@1.0.85 agent
   stdio`, addable on a node today from `agent.catalogue`, generic mark);
   `cursor` (archive, `cursor-agent acp`; Cursor's documentation now says
   `agent acp`); `muse-code` (Meta, archive, `muse acp` with
   `MUSE_EXPERIMENTAL_ACP=on`); `antigravity-acp` (Google, archive, an
   IDE-extension program, not the `agy` CLI); third-party `amp-acp` 0.12.0
   (Apache-2.0, archive) and `pi-acp` 0.0.34 (MIT, npx, addable today).
   Vessel never downloads archives (ADR 0032, decision 5).
2. **Documented wires**: Pi's RPC (`docs/rpc.md` of
   `@earendil-works/pi-coding-agent` 0.84.3, MIT); Antigravity's stream-json
   (Google's headless CLI page); Muse's protocol is generated by `muse
   schema generate-ts` (Paseo vendors it, `PL/muse-provider/server/msp.d.ts`,
   Muse 1.4.1). OMP: no vendor document (Paseo's types `PR/omp/rpc-types.ts`
   only).
3. **Antigravity can run without skipping permissions** (Google's headless
   page): without `--dangerously-skip-permissions`, an action that needs
   approval "is denied, the run continues". Paseo always passes the flag
   (`PL/antigravity-provider/server/process.ts:36-50`).
4. **Pi has no permission prompts by design** (its README: "No permission
   popups"); `--mode rpc` shows no trust prompt. Paseo's extension-UI
   requests become questions (`PR/pi/agent.ts:945-1000`).
5. **Cursor's ACP page** (cursor.com/docs/cli/acp): modes `agent`, `plan`,
   `ask`; `session/request_permission` with `allow-once`, `allow-always`,
   `reject-once`; auth `cursor_login`, `agent login`, `CURSOR_API_KEY`;
   blocking `cursor/ask_question`, `cursor/create_plan`; notifications
   `cursor/update_todos`, `cursor/task`, `cursor/generate_image`.
   `cursor/list_available_models` is not documented there.
6. **Marks are keyed on built-in identity** (ADR 0048: added agents stay
   generic even when named like a known one).
7. **Paseo's defaults that run without asking**: OMP `full` (`--approval-mode
   yolo`, `MAN:255`); Muse served with `--disable-sandbox --trust-workspace`
   (`PL/muse-provider/server/options.ts`); Antigravity's only mode skips
   permissions; the Claude SDK always gets `allowDangerouslySkipPermissions`.

## 1. Decisions taken (coordinator, 2026-11-14)

- **Modes, labels and defaults are Paseo's.** Where an agent has a safer
  mode than Paseo's default (OMP `write`, Antigravity `deny`, Muse with its
  sandbox on), it is offered beside the default. A mode that runs without
  permission prompts is named "Full access" in every list and in the line a
  session shows when it starts in it. If the owner prefers the safer mode,
  only the default changes.
- **Codex's mode ids are Paseo's** (`auto`, `auto-review`, `full-access`).
- **Claude Code**: no mode chosen means `auto`, except under Bedrock or
  Vertex (then `default`; a chosen `auto` is refused there). Models are
  Paseo's curated ids filtered by what the agent's own `initialize` lists.
- **Pi and MCP as Paseo** (ADR 0058, decision 6): `get_commands` first;
  `pi-mcp-adapter` takes a `--mcp-config` file; Pi's own MCP extension takes
  an extension file of Vessel's own calling `pi.registerMcpServer`; neither
  is a typed refusal.
- **Marks**: none of the seven until the owner answers; the generic mark and
  the agent's name meanwhile.
- **Credentials**: a driver never reads an agent's credential files; what
  cannot be done is a typed refusal, never a silent drop.
- **Protocol**: the next free number, 21, provisionally.

## 2. Shared slices (first)

Every slice passes the root gate on its own.

- **P1 (proto, protocol 21)** `vessel-proto`: `HarnessKind` + seven
  variants, names and aliases, `ALL` grows; `HarnessKind::since()` (21 for
  the seven); `agents/older.rs`'s `readable`/`withheld` take kinds as well
  as added agents; `OptionValue.risk: Option<Risk>` and `unattended: bool`
  (left out when false); `NodeSettings.agents_enabled` (per kind, default on
  except `omp`). Regenerate `web/src/wire/`. Tests: round trips, an older
  peer of protocol 20.
- **C0 (harness skeleton)** `vessel-harness/src/harnesses/{grok,cursor,amp,
  pi,omp,antigravity,muse}.rs` + `mod.rs`'s match; `Structured::None`;
  `Descriptor.environment` (`Node` for the four, `Clean { names }` for the
  seven). A session of a `Structured::None` kind is refused at launch
  (`unsupported`, naming the driver it needs) until that driver is built.
  Tests: discovery with fake binaries named like each.
- **C1 (readiness)** `vessel-node/src/readiness.rs`: a sign-in step per
  kind (status command, or a protocol call without a turn); "too old" from
  each kind's minimum. Tests: each fake answers signed in or out.
- **C2 (registry mapping)** `vessel-node/src/catalogue/registry.rs`: entries
  `grok-build`, `cursor`, `amp-acp`, `muse-code` point to the known agent;
  `pi-acp` and `antigravity-acp` stay plain entries.
- **D0 (seam names)** `vessel-agent/src/drivers.rs`: `Driver` + four
  variants, modules with `BUILT = false`. Frozen files (ADR 0057's plan):
  agreed with the Codex and Claude Code drivers' owners before it is made.
- **S1 (naming no-prompt modes)** app side: a value with `unattended` shows
  the dangerous tier and "Runs every action without asking"; the session's
  start line says "Full access". Before any direct driver of the seven is
  `selectable`.

## 3. Per agent

### Codex
- Paseo: `codex app-server` (+`--enable goals` from 0.128.0); modes `auto`
  "Default Permissions", `auto-review` "Auto-review" (default), `full-access`
  "Full Access" (`MAN:77-101`); `model/list`, effort per model, Speed
  select, Plan toggle; steer, rewind, questions, plan approval, MCP.
- Vessel: the Codex driver's slices (ADR 0057) carry it, with Paseo's ids
  and a fixed map from codex-acp's (`agent` -> `auto-review`,
  `workspace-write` -> `auto`, `agent-full-access` -> `full-access`,
  `read-only` kept as a hidden preset); `full-access` is `unattended`.

### Claude Code
- Paseo: Agent SDK driving the person's `claude`; modes `plan`, `default`
  "Always Ask", `acceptEdits`, `auto` (default), `bypassPermissions`
  (`MAN:38-75`); curated models + discovery; effort; Fast.
- Vessel: the Claude Code driver's slices (ADR 0057); `bypassPermissions`
  is `unattended`; the skip flag only with it.

### Grok (catalogue side)
- Paseo: ACP catalogue entry, `grok agent stdio`, generic client.
- `harnesses/grok.rs`: binary `grok`, `Structured::Native { args: ["agent",
  "stdio", "--no-auto-update"] }`; install `npm install -g
  @xai-official/grok` (the registry's package); login `grok login`; sign-in
  from the handshake (`auth_required`); clean env + `XAI_API_KEY`. Mode ids
  as Grok reports them; the always-approve one is tagged `unattended`.
- Real only: the mode and model ids a real `grok agent stdio` reports;
  whether it asks over `session/request_permission` in every mode but
  always-approve.

### OpenCode
- Paseo: `opencode serve` + SDK v2; modes from live agents; Auto Accept
  switch.
- Vessel: ADR 0057's OpenCode slices; Auto Accept as a switch carrying
  `unattended`; sign-in from `opencode auth list` (output read for the
  verdict only).

### Pi (direct driver)
- Paseo: `pi --mode rpc` (+`--model`, `--thinking`, `--session`/
  `--no-session`, `--mcp-config`, `--extension`, `PR/pi/runtime.ts:117-143`);
  requests `prompt`, `steer`, `abort`, `compact`, `set_auto_compaction`,
  `get_available_models`, `set_model`, `set_thinking_level`,
  `get_commands`; no modes; thinking off..max (default medium); rewind via a
  tree navigation (`PR/pi/rewind.ts`).
- Slices (`vessel-agent/src/pi/`, `fake_pi_rpc.rs` replaying `docs/rpc.md`'s
  shapes):
  1. framing (LF only, strip `\r`, never split on U+2028/U+2029 as
     `rpc.md` warns), `prompt`, the event stream, tool calls, `abort`,
     sessions; `get_session_stats` as usage.
  2. questions (`extension_ui_request` dialogs -> questions); then
     `selectable` (after S1).
  3. options: models, thinking levels, commands, `steer`; sign-in from an
     empty model list.
  4. history, rewind, fork (`get_entries`, `get_tree`, `fork`,
     `switch_session`).
  5. MCP as ADR 0058, decision 6.
- Harness: binary `pi`, home `~/.pi/agent` (`PI_CODING_AGENT_DIR`), install
  `npm install -g @earendil-works/pi-coding-agent`, sign-in inside Pi.

### OMP (direct driver)
- Paseo: `omp --mode rpc-ui --approval-mode yolo|write|always-ask`; modes
  `full` (default), `write`, `ask`; a mode change restarts the runtime and is
  refused mid-turn; thinking `auto, off, minimal, low, medium (default),
  high, xhigh, max`; Fast via `set_fast_mode`; min 16.3.9; off by default.
- Slices (`vessel-agent/src/omp/`, reusing Pi's framing): turn and stream;
  approvals and questions, then `selectable`; modes (Paseo's ids and
  default, `full` `unattended`), models, thinking, Fast; rewind and
  sessions; host tools.
- Harness: binary `omp`, install `bun install -g @oh-my-pi/pi-coding-agent`,
  home `~/.omp`. Real only: frame shapes, approval payloads.

### Antigravity (direct driver)
- Paseo: `agy --input-format stream-json --output-format stream-json
  --add-dir <cwd> --disable-slash-commands --dangerously-skip-permissions`;
  one mode `full-access`; models from `agy models`; min 1.1.15.
- Slices (`vessel-agent/src/antigravity/`, `fake_agy_stream.rs` replaying
  Google's headless frames): start, resume, deltas and tools, `result` with
  usage and denied actions (each new denial once), cancel; modes
  `full-access` (Paseo's default, `unattended`) and `deny` (offered beside
  it, no flag); then options (`agy models`), images as files.
- Harness: binary `agy`, sign-in = `agy models` answers.

### Muse Code (catalogue side first, then a direct driver)
- Paseo: `muse serve` with `--disable-sandbox --trust-workspace`; MSP
  JSON-RPC 2.0; modes `onRequest` (default), `promptUnmatched`,
  `denyUnmatched`, `allowAll` (`unattended`); min 1.3.0; sign-in via
  `account/read`.
- Harness: binary `muse`, ACP launch `muse acp` with
  `MUSE_EXPERIMENTAL_ACP=on`; install Meta's installer (shown, not run);
  sign-in `muse login` / `META_API_KEY`.
- Driver slices (`vessel-agent/src/muse/`): connection and turn; approvals
  and questions, then `selectable`; modes, models, effort, usage; session
  list. Paseo's serve flags by default; the sandbox and workspace trust as
  a choice beside them.

### Amp (catalogue side)
- Paseo: catalogue entry `amp-acp` (third-party wrapper), generic ACP.
- `harnesses/amp.rs`: `Structured::Adapter { binary: "amp-acp" }` over the
  agent binary `amp`; shown as "through a third-party adapter"; install:
  Amp's own CLI + the adapter's release (archive: printed, not run); clean
  env + `AMP_API_KEY`, `AMP_CLI_PATH`; its Bypass setting `unattended`.

### Cursor (catalogue side)
1. `harnesses/cursor.rs`: binary `cursor-agent`, `Native { args: ["acp"] }`,
   install `curl https://cursor.com/install -fsS | bash` (shown, not run),
   login `cursor-agent login`, `CURSOR_API_KEY`; modes `agent`, `plan`,
   `ask`.
2. The ACP driver serves what the harness declares (never a name match
   outside `vessel-harness`): the `_meta.parameterizedModelPicker` client
   capability; the model list from `cursor/list_available_models` (model +
   per-model effort), refused with a typed "update Cursor" on `-32601`;
   `fast` as the Fast switch; a probe never sets a model.
3. `cursor/ask_question` -> question, `cursor/create_plan` -> plan approval,
   `cursor/update_todos` -> plan entries; until then the driver answers them
   with a typed refusal, so the tool does not block.

## 4. Where an agent runs without prompts, and how Vessel names it

| Where | Paseo | Vessel |
| --- | --- | --- |
| Antigravity | `--dangerously-skip-permissions` always; "Full access" | `full-access` default (named "Full access"); `deny` offered beside it |
| Pi | no permission system | "Pi asks for nothing: every tool runs as you" in readiness and at start |
| OMP | `full` (`--approval-mode yolo`) default | same default, named; `write` and `ask` beside it |
| Muse | `--disable-sandbox --trust-workspace` served; `allowAll` | same; sandbox and trust as a choice; `allowAll` named |
| Claude Code | skip flag on every session | only with `bypassPermissions` (ADR 0057) |
| Codex | `full-access` | same, named |
| OpenCode | Auto Accept switch | same switch, named |
| Grok | Always-approve | the reported id named |
| Amp | Bypass | named |
| Cursor | `agent`, `plan`, `ask` ask over ACP | none known |

## 5. Order

1. ADR 0058 and this plan.
2. P1 + C0 (the proto and the harness skeleton), then the three ACP agents
   one per slice (Grok, Cursor, Amp), with C1 and C2 for each.
3. Muse over its ACP.
4. D0 and the four direct drivers, in the order agreed with ADR 0057's
   driver owners: Pi, Antigravity, OMP, Muse's own protocol.
5. Marks once the owner and vendors answer.
