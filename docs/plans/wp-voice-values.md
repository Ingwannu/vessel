# Canonical voice settings values carrier

[Decision Log]
- Purpose: let the app compose the Host Voice page against canonical DTOs without inventing a node call, mirroring wire types or importing unfinished dictation/runtime work.
- Existing assets: the five settings files already exist in the voice package and passed its scoped Proto suite. The accepted shared 1f805 alias/getter and two delegated method visibility changes reuse the exact dictation visitor/validator bodies.
- Choice: one values-only producer on announced node head93970acb, with the exact five files from b6f9577c, a metadata-only voice module/None constant and one proto module line. The broader voice package owns the same types; later joining its full module must preserve these definitions.
- Why: typed fake UI can progress while node settings field/Copy conversion, reload, endpoint/model qualification and activation remain separate owners/gates.
- Impact: no RPC row, handler, ErrorDetail, NodeSettings field, Copy conversion, persistence, schema/number, model or runtime. Model identifiers are metadata, not downloads/readiness or approved redistribution.

The source owner of dictation was sent the exact file list before construction.
The announced939 base already contains accepted1f805: dictation/mod.rs,
patch.rs, secret_ref.rs, settings.rs and its speech-audio plan need no import
or duplicate edits. Only value/overlay visibility is widened further. No mutable dictation main ancestry is imported and no function body,
visitor, validator, key lookup or storage policy changes.

Required exact-head VM qualification: root `cargo build -p vessel-node --bin
vesseld` and Proto narrow (TS-enabled library tests, including unchanged
dictation and new voice settings cases). These are owed, not predecessor-suite
substitutions. After scoped V3 source/receipt review the integrator lands this
carrier in merge order. The app consumes only the announced checked carrier
under A8, and its Host Voice page stays unregistered against a typed fake until
the real node settings field and adapter exist. Final voice package runtime,
UI captures, devices/providers/model and broader gates remain separate.
